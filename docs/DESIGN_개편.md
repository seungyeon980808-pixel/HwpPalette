## 0. 방향 한 줄

> 화려해지는 것이 아니라 **조용해지는 것**이다. 하루 수백 번 누르는 도구는
> 반응이 즉각적이고, 화면이 흔들리지 않고, 색이 말을 아껴야 세련돼 보인다.

Emil 의 핵심 명제를 이 프로그램에 맞게 번역하면:

| 원칙 (원문) | 이 프로그램에서의 뜻 |
|---|---|
| 빈도가 높으면 애니메이션 금지 | 팔레트 블럭 클릭(하루 수백 번)은 **무동작 즉시 실행**. 지금도 맞음 — 유지 |
| 모든 UI 모션은 300ms 이하, ease-out | ui_fx 보간(128ms ease-out cubic)은 이미 정답. **적용 범위만 넓힌다** |
| 버튼은 눌린 맛이 있어야 한다 | Tk 는 scale 불가 → **누르는 순간 색 즉시 진해짐 + 글자 1px 하강**으로 번역 |
| 화면은 사용자의 손을 따라야 한다 | **창이 스스로 커지거나 움직이지 않는다** — 이번에 겪은 '위젯이 도망가는' 문제의 일반화 |
| 보이지 않는 디테일이 쌓인다 | 여백 체계·모서리 반경·글자 크기를 **토큰으로 통일** — 한 화면씩 손보는 게 아니라 규칙을 만든다 |
| 색은 상태를 말할 때만 | 창고의 파랑/코랄/초록은 유지, **그 외 장식 색 제거** (팔레트 격자의 네온 초록 등) |

## 1. 현재 상태 진단

### 이미 잘 돼 있는 것 (건드리지 않는다)
- **theme.py 색 일원화** + 밝게/어둡게 두 벌 · WCAG 대비 검증 주석
- **ui_fx 호버 보간** — 128ms ease-out, Emil 권고 그대로
- **RoundButton** · **Popover**(윈도우 기본 메뉴 대체) · **Pretendard Medium** 자동 감지
- 키보드 흐름(표 창의 Enter/↓ 이동, Esc 닫기)

### 문제 목록 (심한 순)

**P1 — 화면이 흔들린다.**
`_fit_window` 가 내용 변화마다 창 크기를 다시 재고, 판이 붙었다 떨어지며
위치까지 바뀐다. 사용자가 직접 지적한 그 문제("버튼을 누를 때마다 버벅").
설정 창은 고쳤지만 같은 패턴이 메인 창·표 창·물감 설정 창에 남아 있다.

**P2 — 창마다 얼굴이 다르다.**
`messagebox.showinfo/askyesno` 가 수십 곳 — 윈도우 기본 회색 대화상자가
불쑥 나와 프로그램의 얼굴을 깬다. tk.Button(네모)과 RoundButton(둥근)이 섞여
있고, Entry 는 `relief="solid" bd=1` 하드코딩이 흩어져 있다.

**P3 — 색이 말이 많다.**
팔레트 격자의 블럭 사용자 색이 원색(네온 초록 #00ff00 계열)까지 허용돼
화면에서 제일 시끄러운 것이 내용이 아니라 장식이다. 강조색(#0071e3)과
CLAUDE.md 시그니처(#0969da)가 갈라져 있는 것도 정리 대상.

**P4 — 간격·크기에 체계가 없다.**
padx=6/8/10/12/14/16 이 파일마다 제각각. 모서리 반경도 6/7/8 혼재.
글자 크기 fs(7)~fs(12) 를 자리마다 임의로 고른다.

**P5 — 상태 전달이 약하다.**
포커스 링 없음(키보드로 어디에 있는지 안 보임), 스크롤바가 윈도우 기본,
로딩 중(한글 변환 몇 초)에 아무 표시가 없다.

## 2. 개편안

### A. 디자인 토큰 (theme.py 확장) — 모든 것의 기반
```python
# 간격 — 4의 배수만. 이 다섯 개 밖의 숫자는 쓰지 않는다
SP = {"xs": 4, "s": 8, "m": 12, "l": 16, "xl": 24}
# 모서리 — 컨트롤 6 / 카드 10 / 창 판 12
RADIUS = {"ctl": 6, "card": 10, "pane": 14}   # 6 →+4→ 10 →+4→ 14 (동심원)
# 글자 위계 — 창 제목 12 / 절 제목 10 / 본문 9 / 보조 8 / 캡션 7 (fs() 배율 적용)
# 모션 — 호버 128ms ease-out(8단계 × 16ms) / 누름 0ms 즉시 / 등장 정지(무동작)
```
> Emil: "unseen details compound". 토큰이 있어야 서른 개 화면이 한 손으로 그린 것처럼 보인다.

### B. 색 정리
- 강조색 **한 개**(#0071e3 유지 — 애플 A안 사용자 결정 존중, CLAUDE.md 는 갱신)
- 상태색은 창고 3색(파랑=안 씀 · 코랄=이 팔레트 · 초록=선택)과 위험 빨강뿐
- **블럭 사용자 색을 파스텔 12색 팔레트로 제한** — colorchooser 자유 선택 제거.
  기존에 고른 원색은 가장 가까운 파스텔로 자동 매핑
- 격자의 도구 블럭 기본색도 채도 한 단계 낮춤

### C. 컴포넌트 통일 (새 파일 `widgets.py`)
- `dialog()` — messagebox 전면 대체. Popover 와 같은 얼굴, 기본 버튼이 항상
  안전한 쪽, Enter/Esc 규칙 통일. **이것 하나가 체감 개선의 절반**
- `Field` — Entry 래퍼: 포커스 시 강조색 테두리 2px (포커스 링)
- `Scrollbar` — ttk 스타일로 가는 회색 막대
- RoundButton 에 **누름 피드백**: press 순간 배경 15% 진해짐 + 글자 1px 하강,
  release 에 즉시 복귀 (전환 없음 — 누름은 즉각이어야 한다)
- 로딩 상태: 한글 연결·HWPX 변환 동안 버튼 글자를 "여는 중…"으로 바꾸고 잠금

### D. 모션 규칙 (늘리는 게 아니라 **금지를 명문화**)
| 자리 | 규칙 |
|---|---|
| 팔레트 블럭 클릭 | **무동작.** 지금처럼 즉시 실행 |
| 호버 | 128ms ease-out 보간 — 창고 타일·팔레트 탭에도 확대 적용 |
| 누름 | 0ms 색 변화 (C 참조) |
| 창 열림 | 등장 애니메이션 없음. **자리만 규칙적으로**(screens.place_beside) |
| 창 크기 | 사용자가 창을 연 뒤에는 **프로그램이 크기·위치를 바꾸지 않는다**. 내용이 넘치면 스크롤 |
| 스포트라이트(튜토리얼) | 유지 — 첫 경험 1회짜리라 Emil 기준으로도 허용 |
> 스프링·블러·드래그 모멘텀은 **안 한다** — Tk 에서 억지로 흉내내면 그게 바로 '버벅'이다.

### E. 화면별 적용 순서
1. **메인 팔레트 창** — 제일 자주 본다. 토큰 적용, 격자 색 정돈, 하단 버전 표기 정리
2. **설정 창(팔레트·창고·상세)** — P1 잔재 제거, 3판 머리말 통일, 스크롤바 교체
3. **대화상자 일괄 교체** — messagebox → widgets.dialog (기계적 치환, 파일 단위)
4. **표 창 둘(양식·템플릿)** — Field 적용, 로딩 표시
5. **물감 나누기·도움말·튜토리얼** — 마지막 (빈도 낮음)

### F. 하지 않는 것
- 웹뷰·이미지 기반 UI 재작성 (배보다 배꼽)
- 다크 모드 실시간 전환 (재시작 방식 유지 — 기존 결정)
- 아이콘 폰트 도입 (이모지 두 벌 아이콘 체계가 이미 있음)

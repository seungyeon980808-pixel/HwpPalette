# 인수인계 — 보기 박스 템플릿 하나로 줄이기 + 변환 취소 (2026-07-27)

> 이 문서는 **대화만 오간 상태**의 인수인계다. **코드는 한 줄도 고치지 않았다.**
> 사용자가 한글에서 서식 설정을 한 것까지만 진행됐다.

## 한 줄 요약

보기 개수(3·4·5)마다 물감을 따로 저장해야 하는 문제를 **한글 문단 번호**로 없앴다.
이제 남은 일은 ① 실측 확인 2건 ② `{ }` 문법 없이도 되게 할지 결정 ③ "방금 변환 취소" 기능 구현이다.

---

## 1. 원래 문제

`〈보 기〉` 박스 안의 ㄱ. ㄴ. ㄷ. 항목 수가 문항마다 다른데, 템플릿은 빈칸(`\`)을
**고정 개수**로만 가질 수 있다. `fill_slots` 는 빈칸을 찾아 채울 뿐 **늘리지 못한다**
([engine_library.py](../engine_library.py) `fill_slots`).

그래서 팔레트에 `3보기` `4보기` `5보기` 를 따로 만들어야 했다. 사용자가
"너무 귀찮다"고 지적.

## 2. 해결한 것 — 한글 문단 번호 (코드 수정 없음)

불릿박스는 Enter 마다 ○ 이 나오는데 보기박스는 안 나왔다.
**불릿박스는 글머리표(서식)이고, 보기박스의 ㄱ.ㄴ.ㄷ. 은 손으로 친 글자**였기 때문.

보기 항목 문단에 **문단 번호**를 걸면 Enter 마다 ㄴ. ㄷ. ㄹ. 이 자동으로 붙는다.

설정 (한글에서 사용자가 이미 완료):

1. 보기 항목 문단에 커서 → `Ctrl+K, N` (문단 번호 모양)
2. 사용자 정의 → **번호 서식 `^1.`** / **번호 모양 `ㄱ,ㄴ,ㄷ`** / **시작 번호 `1`**
3. 상위 창(문단 번호/글머리표)에서 **"새 번호 목록 시작"** 체크

### 3번 체크가 반드시 필요한 이유

문단 번호는 **문서 전체에서 하나로 이어진다.** 이 체크가 없으면 두 번째 보기 박스가
ㄱ. 이 아니라 **ㅁ. 부터 시작**한다. 사용자가 실제로 이 증상을 겪었고,
체크를 켜니 해결됐다("제대로 따라오네").

⚠️ 이 체크는 **박스의 첫 항목 문단(ㄱ. 자리)에만** 걸어야 한다. 둘째 줄에 걸면
거기서부터 다시 센다.

## 3. 마크다운으로 넣는 방법 — `{ }` 덩어리 (이미 구현돼 있음)

빈칸 하나에 **여러 줄**을 넣는 기능이 이미 있다.
[parser.py](../parser.py) `_read_block` / `MultiLine`,
[engine_library.py](../engine_library.py) `fill_slots` 의 `MultiLine` 분기.

```
\보기\
{가나다
라마바
가}
```

빈칸 하나에 세 문단이 들어가고 줄 사이는 `BreakPara` 로 나뉜다. 그 문단들에
문단 번호가 걸려 있으니 **ㄱ. ㄴ. ㄷ. 이 자동으로 붙는다.**

괄호를 따로 한 줄에 둬도 된다. 덩어리 안에서 라벨·서식·`\표3*3\` 도 통한다.

### 그래서 템플릿은

- 보기 박스 안에 **빈칸 `\` 하나만** (`slot_count = 1`)
- 그 줄에 문단 번호 + "새 번호 목록 시작" 이 걸려 있어야 함
- 팔레트 칸은 **`보기` 하나**로 끝. 기존 `3보기`·`4보기`·`5보기` 물감은 삭제

저장은 팔레트의 **"+ 지금 선택 영역을 템플릿으로 저장"**
([library_ui.py](../library_ui.py)). 내부적으로 복사 → 새 탭 붙여넣기 → 파일 저장이라
서식이 그대로 간다 ([engine_library.py](../engine_library.py) `capture_fragment`).

## 4. 다음 세션이 **먼저 해야 할 실측 2건**

둘 다 한글을 켜야 확인할 수 있어서 이번 세션에서 못 했다. **여기서 결과가 갈린다.**

### 실측 A — 물감 저장·삽입 후에도 "새 번호 목록 시작"이 살아남는가

물감 저장은 `Copy` → 새 탭 `Paste` → 저장이고, 삽입도 붙여넣기 계열이다.
**붙여넣기 과정에서 문단 번호 속성이 떨어져 나갈 수 있다.**

> 확인 방법: 새 문서에 그 물감을 **연달아 두 번 삽입**한다.
> - 둘 다 ㄱ. 부터 → 통과. 추가 작업 없음.
> - 두 번째가 ㅁ. 부터 → **삽입 직후 앱이 "새 번호로 시작"을 자동으로 걸어주는 코드가 필요.**
>   그 동작에 해당하는 HWP 액션 이름은 **추측하지 말고 실측으로 확인할 것**
>   (액션명을 틀리게 넣으면 조용히 실패한다).

### 실측 B — `BreakPara` 로 나눈 문단에도 번호가 붙는가

`{ }` 덩어리는 사용자가 Enter 를 치는 게 아니라 API 로 `BreakPara` 를 실행한다.
손으로 Enter 칠 때와 동작이 같은지 확인이 필요하다.

> 확인 방법: `\보기\` + `{세 줄}` 로 실제 변환해서 ㄱ. ㄴ. ㄷ. 이 붙는지 본다.

## 5. 미결정 — `{ }` 없이도 되게 할까

사용자 질문: "`{ }` 없이는 안 되는 건가?"

**지금은 안 된다.** 파서는 `\라벨\` 다음 줄부터 **한 줄 = 빈칸 하나**로 담는다
([parser.py](../parser.py) `build_library_plan`). `{ }` 가 "이 여러 줄을 한 칸으로 세라"는
표시다.

### 만든다면 이 규칙

> **빈칸이 1개뿐인 템플릿(`slot_count == 1`)** 은, 빈 줄이나 다음 `\마커\` 가 나올 때까지의
> 연속된 줄을 전부 그 한 칸에 넣는다.

끝을 알리는 신호는 파서에 이미 있다 — 빈 줄과 `_starts_new_insert`.
**`slot_count == 1` 한정이 핵심**이다. 빈칸이 여러 개인 템플릿까지 바꾸면 기존 물감이 전부 깨진다.

### 이번 세션의 의견 (사용자 결정 대기)

`{ }` 를 그냥 쓰는 쪽을 권했다.
- 이미 동작하므로 오늘 바로 쓸 수 있다
- 경계가 눈에 보인다. 빈 줄로 끊는 방식은 실수로 빈 줄 하나 넣으면 뒷줄이 **조용히**
  템플릿 밖으로 빠져나가고, 인쇄물을 보기 전엔 모른다

단, **AI 에게 마크다운을 받아쓰게 하는 경우** 중괄호를 빼먹는 실수가 잦다면 값을 한다.

## 6. 마크다운 역변환 — 안 만들기로 결론

사용자가 물었으나, 목적을 확인하니 **"수정하다가 잘못된 거 있으면 고치려고"** 였다.
그 목적에는 역변환이 필요 없다.

참고로 역변환 자체는 부분적으로 이미 있다 — [form_markdown.py](../form_markdown.py) 가
`GetTextFile("HWPML2X")` 로 표까지 담긴 구조를 뽑는다. 다만 **AI 에게 구조를 보여주는
읽기 전용**이고, 편집 가능한 마크다운으로 되돌리는 게 아니다.

진짜 역변환이 어려운 이유: 삽입된 HWP 블록을 보고 "이건 `보기` 물감이다"를 알아낼
흔적이 문서에 없다. 붙여넣고 나면 그냥 테두리 있는 문단 뭉치다.

**역변환이 값을 하는 경우는 "남이 준 hwp 를 내 물감 체계로 옮길 때"** 정도다.
그 요구가 생기면 그때 다시 검토한다(스타일 이름 → 물감 라벨 매핑 방식이 유력).

## 7. 다음 작업 — "방금 변환 취소" 기능

사용자 요구: **"Ctrl+Z 를 아주 많이 눌러야 해서 귀찮다. 한 방에 이전으로 돌릴 수 없나."**

### 사용자가 제안한 "타수만큼 Undo" 는 쓰지 말 것

한글의 **되돌리기 단위는 우리가 실행한 동작 수와 다르다.** 여러 동작을 하나로 묶기도,
하나를 여럿으로 쪼개기도 한다(표 삽입·서식 적용에서 특히).
횟수가 모자라면 어중간하게 남고, **넘치면 사용자가 그 전에 써 둔 글까지 지운다.**

### 대신 — 삽입 범위를 이미 알고 있다

재료 세 가지가 모두 있다.

| 재료 | 위치 |
|---|---|
| `anchor` — 삽입 시작 위치 | 변환 실행부에서 이미 계산 |
| `end_para` — 삽입물이 끝난 문단 번호 | [engine_library.py](../engine_library.py) `measure_insert_span` |
| `restore_text(text)` — 지운 원문을 되돌린다 | [engine_library.py](../engine_library.py) |

> 변환 직후 `(anchor, end_para, 원본 마크다운)` 을 기억해 둔다 →
> 취소를 누르면 **그 범위만** 선택해 지우고 → 원문 마크다운을 그 자리에 되돌린다.

Ctrl+Z 횟수를 셀 필요가 없고 지우는 범위가 명시적이라 남의 글을 건드리지 않는다.

### 반드시 붙일 안전장치

1. **변환 직후 1회만 유효.** 그 사이 사용자가 문서를 편집하면 `end_para` 가 어긋나
   엉뚱한 문단을 지운다. 문서가 바뀌었으면 **거부하고 Ctrl+Z 를 안내**할 것.
   안전한 실패 방향은 "취소가 안 된다" 이지 "남의 글이 사라진다" 가 아니다.
2. **커서가 표 안이었으면 `end_para` 가 `None`** 이다
   ([engine_library.py](../engine_library.py) `measure_insert_span`). 범위를 모르므로
   그 경우에도 취소를 막고 안내.

### 미결정 (사용자에게 물어볼 것)

**취소 후 마크다운 원문이 그 자리에 돌아오는 게 맞는가?** 아니면 삽입물만 지우고 빈
자리로 둘 것인가. 이번 세션 의견은 **원문 복원** — 고쳐서 바로 다시 변환할 수 있다.

### UI 제안

팔레트에 **"방금 변환 취소"** 버튼 하나. 변환 직후에만 활성화되고, 조건이 안 맞으면
비활성 + 이유 표시.

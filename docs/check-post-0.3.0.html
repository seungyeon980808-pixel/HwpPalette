준비: 한글을 먼저 띄워 두고 python main.py 로 프로그램을 실행합니다. ①~③ 은 한글이 필요하고, ④~⑦ 은 프로그램만으로 확인됩니다. 이상한 것이 보이면 내 물감 폴더의 app.log 를 함께 알려 주십시오 — 실패가 로그로만 남는 자리가 몇 군데 있습니다.

① 양식 수정 왕복 031 · 032 — 이번 라운드에서 가장 중요

◫(Ctrl+D)로 도킹 → ⚙(Ctrl++) → 창고에서 템플릿/양식 물감 → [수정] → [양식 수정] → [덮어씌워 저장]. 그다음 [취소]로도 한 번.

✓번호문제 (예전 모습)목표 동작확인점
032 한글이 두 자리를 왕복하며 버벅였다. 메인 도킹과 양식 수정이 같은 한글 창을 서로 끌어당겼다. 주인은 하나. 양식 수정이 메인 도킹보다 세다 — 시작할 때 한 번, 끝날 때 한 번만 옮긴다. 편집으로 들어가고 나올 때 한글이 딱 한 번씩만 움직이는가. 왕복·떨림이 없는가.
032 양식 수정 중에 메인 ◫ 를 누르면 두 창이 한글을 다퉜다. 낮은 쪽은 뺏지 않는다 — 안내만 뜨고 아무 일도 안 일어난다. 편집 중 ◫ → “양식 수정이 한글을 쓰고 있습니다” 안내만 뜨는가.
031-a 편집을 마치면 설정 창이 세로로 길쭉하게 커지고, 마우스로 줄일 수도 없었다. 편집 전 크기로 돌아온다. 커졌더라도 마우스로 줄일 수 있다. 저장/취소 뒤 창 크기가 그대로인가. 모서리를 끌어 줄여지는가.
031-b 편집이 끝나면 한글에 빈 문서 1 이 남았다. 쓰고 난 임시 문서를 정리한다. 편집 뒤 한글 탭에 쓸데없는 빈 문서가 안 남는가.
구멍 편집을 마치면 창의 판 자리가 통째로 잘려 초록 바탕이 비쳤고, ✕ 도 안 먹었다. 오려 낸 자리를 어느 길로 끝나든 메운다(저장·취소·실패 전부). 저장/취소 뒤 창이 안 잘리는가. ✕ 로 닫히는가.

② 도킹 화면이 안 비는가 035 · 036

✓번호문제 (예전 모습)목표 동작확인점
035 도킹 중 팔레트 고르개(▾) 를 열면 판이 하얗게 비었다. 팝오버가 뜨는 순간 창 순서가 어긋났다. 판이 열려도 한글이 계속 보인다 — 판이 뜰 때 창 순서를 다시 잡는다. 도킹 상태에서 팔레트 고르개를 열었다 닫는다 → 한글이 계속 보이는가.
036 PageUp(항상 위 토글)을 누르면 도킹 화면이 하얗게 비었다. 우리 창이 최상위 띠로 올라가 한글을 그 아래 둘 수 없었다. 도킹 중에는 ‘항상 위’를 바꿀 수 없다 — 안내만 뜬다. 도킹 중 PageUp → 도킹이 유지되고 “도킹 중에는 바꿀 수 없습니다” 안내가 뜨는가.
036 — 원래 기능은 안 죽였다. 도킹을 뗀 뒤 PageUp → ‘항상 위’가 정상으로 켜졌다 꺼지는가.
구멍 구멍 뚫기가 죽어 있어(정의가 지워짐) 도킹이 창 순서 하나에만 기대고 있었다. 판 자리를 실제로 오려 내어 한글이 그 자리에 보인다. 도킹한 채 메인 창을 끌어 옮겨 본다 → 한글이 어긋남 없이 따라오고, 한글 안이 클릭·타이핑 되는가.

③ 누르면 무슨 일이 일어나는가 040 · 033 · 034 — 한글 필요

✓번호문제 (예전 모습)목표 동작확인점
040 \ 만 있는 물감은 바로 꽂히고, \이름\ 이 있으면 표가 떴다 — 물감마다 동작이 달라 예측이 안 됐다. 안 A(확정). 빈칸이 있으면 늘 같은 옵션 팝오버가 그 칸 아래에 뜬다: 빈칸인 채로 꽂기 / 채워 넣고 꽂기. 빈칸이 없으면 즉시 꽂는다. \ 만 있는 템플릿과 \이름\ 있는 양식을 각각 눌러 본다 → 둘 다 같은 팝오버가 뜨는가. 빈칸 없는 물감은 바로 꽂히는가.
040 이름 없는 \ 만인 템플릿은 채우기 표로 갈 길이 없었다. 표가 ‘빈칸 1, 2…’ 로 받는다. \ 만 있는 템플릿에서 채워 넣고 꽂기 → 표가 뜨고 빈칸이 번호로 나오는가.
033-a 수능양식: 카드에는 “빈칸 2”인데 채우기 창은 “채울 자리 1개” 였다. 원인은 글상자가 아니라 <hp:fwSpace/>(고정폭 공백) 뒤에 숨은 \ 였다. 등록할 때와 채울 때가 같은 개수를 본다. 수능양식을 눌러 채우기 창을 연다 → 빈칸이 2개 다 나오는가. 둘 다 채워 꽂으면 문서에 둘 다 들어가는가.
034 표 안 문단을 선택해 자간 맞춤 → “다듬을 문단을 찾지 못했습니다 (표 안은 제외됩니다)”. 표 셀 안에서도 동작한다. 어절 단위 줄나눔 + 자간 좁히기가 셀 문단에 걸린다. 보기 박스(ㄱㄴㄷ) 셀 하나를 선택해 자간 맞춤 실행 → 잘림이 사라지는가. Ctrl+Z 한 번에 원복되는가.
034 — 여러 셀에 걸친 선택은 1차 제외 — 안내로 막는다. 셀 두 개 이상을 걸쳐 선택해 실행 → “표에서는 셀 하나씩 선택해 주세요” 가 뜨는가.
034 — 본문 동작은 안 건드렸다. 표 바깥 본문 문단에 자간 맞춤 → 예전처럼 정상인가 (회귀 확인).

④ 특수기호 창 028 — 회귀 복원

여는 곳 두 군데를 둘 다 봐야 합니다: 팔레트 빈칸 클릭 → 특수기호, 그리고 ⚙ → 창고 → 특수기호 → ＋.

✓번호문제 (예전 모습)목표 동작확인점
028 팔레트에서 연 특수기호 창에 종류별 묶음이 없었다 — 검색칸 하나뿐. 022 를 반영할 때 기능이 적은 창으로 합친 것이 원인. 왼쪽에 묶음 목록 21갈래(전체 · 내가 등록 · 원문자 · 로마숫자 · 수학 …). 팔레트 빈칸에서 연 창에 왼쪽 묶음 목록이 있는가. 눌러 보면 그 묶음만 나오는가.
028 내가 등록한 기호가 그 창에 안 보였다. ‘전체’와 ‘내가 등록’에 함께 나오고 검색에도 걸린다. 내가 만든 특수기호 물감이 보이는가. 이름으로 검색되는가.
028 425개 중 앞 96개만 보이고 나머지는 검색으로만 찾을 수 있었다. 상한 폐지. 대신 나눠 그리기로 버벅임을 막는다. ‘전체’를 골라도 끝까지 다 나오는가. 창이 버벅이지 않는가.
028 두 창이 각자 목록을 만들어 한쪽만 기능이 빠졌다. 목록 규칙은 한 곳(char_source)이고 두 창이 공유한다. 창고 ‘특수기호’ 탭과 팔레트 쪽 창의 묶음·개수가 같은가.

⑤ 창고에서 하는 일 038-a · c · d · 039

✓번호문제 (예전 모습)목표 동작확인점
038-a 물감 우클릭에 삭제가 없었다 — 지우려면 다른 창으로 가야 했다. 우클릭 = 삭제 전용. 지우기 전에 함께 사라지는 팔레트 자리 수를 세어 보여준다. 물감 우클릭 → 삭제만 있는가. 팔레트에 놓아 둔 물감을 지우려 하면 “팔레트에 놓여 있는 N자리도 함께 사라집니다” 가 뜨는가.
038-a — 꾸러미(섞기)가 쓰는 물감은 못 지운다 — 지우면 빈칸 수가 조용히 줄어 시험지가 어긋난다. 꾸러미에 든 요소 물감을 지워 본다 → 막히고, 누가 쓰는지 이름이 나오는가.
038-c ‘옮기기’ 목록에 지금 있는 분류까지 떠서, 눌러도 아무 일이 없는 항목이 늘 하나 있었다. 목록 자체가 없어졌다(아래 038-d). 우클릭에 ‘… 로 옮기기’ 가 아예 없는가.
038-d 분류 옮기기가 우클릭 메뉴였다. 물감을 위쪽 하위 분류 탭에 끌어다 놓으면 그 분류로 간다. 물감을 하위 분류 탭 위로 끌어 놓는다 → 그 분류로 옮겨지는가. 끌고 지나갈 때 탭이 강조되는가.
038-d — Ctrl 로 담아 둔 것은 전부 옮긴다. 탭 밖에 놓으면 예전처럼 팔레트로 간다. Ctrl 로 여럿 담고 하나를 끈다 → 전부 옮겨지는가. 탭 밖(팔레트 격자)에 놓으면 블럭이 꽂히는가 (회귀 확인).
039 도구 ‘라이브러리’ 는 설정 창을 통째로 여는 버튼일 뿐이었다 — 창고가 같은 일을 더 잘한다. 도구 목록에서 없어지고, 이미 팔레트에 놓여 있던 블럭도 걷힌다. 도구 목록·창고 ‘도구’ 탭에 라이브러리가 안 보이는가(7개 → 6개). 놓아 뒀던 칸이 사라졌는가.
039 — 설정 창 자체는 남긴다 — 특수기호·사진이 같은 창을 다른 입구로 쓴다. 도구 특수기호와 사진 폴더 관리가 그대로 동작하는가 (회귀 확인).

⑥ 겉에서 보이는 표시 037 — 안 B

✓번호문제 (예전 모습)목표 동작확인점
037 한 칸에 물감이 여러 개 겹쳐 있어도 겉에서 알 수 없었다 — “답안” 칸에 여섯 개가 든 것을 눌러 보기 전에는 몰랐다. 칸 오른쪽에 청록 세로 띠 + 개수. 겹친 칸(예: 답안)에 청록 띠와 숫자가 보이는가. 개수가 맞는가.
037 꾸러미(섞은 물감)도 구분이 안 됐다. 꾸러미는 보라 MIX 띠. 꾸러미 물감 칸에 보라 MIX 가 보이는가.
037 — 표시는 한 부품(ribbon)이고 세 화면이 같은 것을 쓴다. 칸 크기는 안 변한다. 메인 팔레트 · 설정 격자 · 창고 카드 세 곳의 표시가 같은 모양인가. 띠가 붙었다고 칸이 커지거나 글자가 밀리지 않는가.

⑦ 도구 판 · 서식 만들기 창 027 · 029 · 030

✓번호문제 (예전 모습)목표 동작확인점
029 사진 폴더를 연결하려면 [설정] 단추가 다섯 탭짜리 창을 통째로 열었다 — “전혀 바뀐 게 없다”던 그 자리. 폴더 관리가 도구 판 안으로. 폴더마다 이름 · 장수 · [↑][↓][해제], 맨 아래 [＋ 폴더 연결]. 창고에서 도구 사진 을 고른다 → 오른쪽 판 안에서 폴더를 연결·해제할 수 있는가. 딴 창이 안 뜨는가.
029 폴더 순서를 바꿀 길이 없었다 — 순서가 곧 이름 충돌 우선순위인데도. [↑][↓] 로 순서를 바꾼다. 폴더를 ↑↓ 로 올리고 내릴 수 있는가. 바꾼 순서가 다시 열어도 유지되는가.
027 도구를 골랐을 때 오른쪽 판의 아래쪽이 비어 있었다. 그 자리에 사용법이 들어간다. 도구를 몇 개 눌러 본다 → 판에 사용법 설명이 나오는가. 도구마다 내용이 다른가(한 문구가 돌려쓰이지 않는가).
030 서식 만들기 창이 17줄이 죽 늘어선 모양이고, 윈도우 기본 체크박스·수치칸이라 프로그램과 얼굴이 달랐다. 글자 · 문단 · 여백 세 카드로 묶고, 자체 Check(둥근 네모, 켜지면 강조색+✓)와 Spin(수치칸+▴▾)으로 갈았다. 서식 만들기 창이 세 카드로 묶여 있는가. 체크·수치칸이 프로그램 얼굴인가. ▴▾ 로 숫자가 오르내리는가.
030 — 카탈로그에 새 항목이 생겼는데 카드 목록에 없으면 맨 아래에라도 나온다 — 조용히 사라지지 않게. 서식 항목이 하나도 빠지지 않았는가(예전 창과 개수 비교).
030 — 만든 서식은 예전과 똑같이 동작해야 한다. 세 카드에서 값을 고쳐 서식 물감을 만들고 실행 → 한글에 그대로 먹는가 (회귀 확인).
참고 — 확인과 무관한 환경 문제 하나. 작업 중 pywin32 의 COM 캐시(%TEMP%\gen_py)가 비워져 한글 연결이 실패하는 일이 몇 번 있었습니다. 프로그램 잘못이 아니라 임시 폴더가 청소되면서 생기는 것으로 보입니다. “한글에 연결하지 못했습니다”가 이유 없이 뜨면 프로그램을 껐다 켜 보시고, 그래도 계속되면 알려 주십시오 — 캐시를 안전한 곳으로 옮기는 방법이 있습니다.

# 임베드(SetParent) 재검토 — 실측 기록 (2026-07-29)

`hwp_dock.py` 머리말은 임베드를 "검토 끝에 버렸다"고 적어 두었지만 **근거가
추측이었다.** 이번에 `spikes/embed_spike.py` 로 전용 한글 인스턴스를 띄워
직접 재봤다. 선생님이 열어 둔 한글에는 손대지 않았다(DispatchEx 로 새 프로세스).

## 잰 것과 결과

| 항목 | 결과 |
|---|---|
| SetParent 자체 | ✅ 된다. `GetParent` 가 우리 Tk 프레임 핸들로 바뀐다 |
| 제목줄 떼고 판에 꽉 채우기 | ✅ 된다 (`WS_CHILD` + 스타일 제거 + `SetWindowPos`) |
| 임베드 중 COM | ✅ 멀쩡하다. `InsertText` 0.02~0.14초 |
| 임베드 중 우리 이벤트 루프 | ✅ 계속 돈다 (심장박동 카운터 증가) |
| 정상 해제 | ✅ 원래 창으로 돌아오고 COM 도 그대로 (단, **창 위치는 0,0 으로 남았다** — 원복 코드 보완 필요) |
| **부모(우리 판)를 파괴하면** | ❌ **한글이 죽는다.** 창 핸들은 3초 넘게 살아 있는 척하다가, 이후 COM 호출이 6초 매달린 뒤 `RPC 실패`. 프로세스는 사라졌고 **저장하겠냐고 묻지도 않았다** |

마지막 줄이 결론을 정한다. 우리 앱이 닫히거나(정상 종료 순서를 놓치거나)
예외로 죽으면, 선생님이 고치고 있던 문서가 **저장 프롬프트도 없이** 함께
사라진다. 이 도구의 존재 이유가 "문항 작업 중 원문 소실 방지"인데
(`docs/NEXT.md` 의 변환 롤백 작업이 그 이야기다), 그 반대편에 새 소실 경로를
하나 만드는 셈이다.

## 아직 못 잰 것 (사람 눈이 필요)

`python spikes\embed_spike.py` 로 창을 띄워 ①②를 누른 뒤 직접 확인:

1. **IME** — 임베드된 한글에 한글 타자·한자 변환이 정상인가
2. **입력 큐 결합** — 한글에서 파일>열기 같은 대화상자를 띄웠을 때 좌상단
   '심장박동' 숫자가 멈추는가 (멈추면 한글이 멎을 때 우리도 멎는다)
3. **4K/배율** — 자식 창이 된 뒤 글씨가 깨지거나 흐려지는가

②까지만 눌러 보고 ⑤(파괴 시험)는 누르지 않아도 된다 — 이미 결과를 알고 있다.

## 판단

**도킹을 유지한다.** 임베드는 "창 하나가 더 뜬 느낌"을 없애 주지만, 대가가
문서 소실 위험이다. 얻는 게 미관이고 잃는 게 원고라면 바꿀 이유가 없다.

도킹이 지금 주는 어색함(창 테두리·제목줄이 판 위에 보이는 것)은 임베드까지
가지 않고도 줄일 수 있다:

- 도킹 중에만 한글 제목줄·테두리를 떼기 (`WS_CAPTION` 제거, 부모는 그대로) —
  SetParent 를 안 쓰므로 파괴 연쇄가 없다. **다음에 시험해 볼 값어치가 있다.**
- 소유자(owner) 로 묶어 z-order·최소화를 함께 움직이기 — 단, 소유자 파괴도
  소유된 창을 파괴하므로 위험은 임베드와 같다. 권하지 않는다.

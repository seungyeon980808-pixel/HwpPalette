## 1. 굵직한 것

### 디자인 전면 개편 — 목업으로 고르고, 고른 것만 코드에 넣었습니다

이번에는 코드를 바로 고치지 않았습니다. 지금 실행 중인 창을 그대로 옮긴 목업을 만들어 **한 번에 한 가지씩만 바꾼 시안**(메인 창 6종 · 격자 칸 3종 · 도구줄 크기 5안)을 눈으로 비교한 뒤 확정했고, 확정된 것만 구현했습니다. 글자 위계나 격자 칸 크기 같은 문제는 숫자만 보고 정할 수 없기 때문입니다.

확정된 내용은 이렇습니다.

- **블럭이 흰 카드가 됐습니다 (시안 H).** 종류별 파스텔 배경을 없애고 전부 흰 카드 + 얇은 테두리로 통일했습니다. 블럭이 여덟 개만 돼도 화면에서 제일 먼저 보이는 것이 이름이 아니라 색 덩어리였기 때문입니다. 색이 하던 "무슨 종류인가"는 이름 위에 선 아이콘이 넘겨받습니다. 아이콘에 이모지는 쓰지 않습니다 — 윈도우에서 컬러로 그려져 색을 아낀 뜻이 깨집니다.
- **공통 팔레트는 아이콘 주도, 개인 팔레트는 글자만.** 개인 블럭은 종류가 몇 가지 안 돼서, 같은 기호가 스무 칸 반복되면 뜻이 아니라 무늬가 됩니다. 그래서 개인 팔레트에는 아이콘을 그리지 않고 이름만 가운데 정렬로 둡니다.
- **공통 팔레트 아이콘은 이후 25% 줄였습니다** (16→12pt, 두 줄 블럭은 13→10pt). 시안대로 키워 놓고 보니 아이콘이 이름을 누르는 느낌이라, 이름은 그대로 두고 기호만 한 발 물렸습니다.
- **글자 위계를 5단에서 4단으로.** 예전 위계는 확대 배율을 거치면 16/13/12/11/10pt 가 되어 가운데 세 단계가 1pt 간격이었습니다 — 특히 가장 많이 쓰이는 두 단계(본문과 보조)가 사실상 같은 크기라, 화면 글자의 절반이 위계 없이 서 있었습니다. 이제 실제 크기 17/15/12/10pt, 간격이 뚜렷합니다.
- **팔레트 설정의 배치 격자 칸을 최소 24px 로** (WCAG 2.5.8 최소 클릭 크기). 한 줄 칸 수는 24개에서 16개로 줄지만, 실제 저장된 팔레트를 재 보니 가장 넓은 것이 15열이라 잃는 것이 없음을 확인한 뒤 결정했습니다. 창 폭은 유지합니다.
- **디자인 토큰을 실제 코드와 맞췄습니다.** 감사해 보니 움직임 토큰(MOTION)이 정의만 되고 읽히는 곳이 0곳이었고, 토큰은 호버 130ms 라는데 코드는 128ms 로 돌고 있었습니다. 코드가 토큰을 읽도록 배선하고 값은 실측치 128 로 통일했습니다(128인 이유 — 16ms 프레임 주기의 배수여야 중간 색이 버려지지 않습니다).

### 한글과 도킹 — 메인 창이 한글을 감쌉니다

v0.2.0 의 도킹은 양식을 고치는 동안만이었습니다. 이제 도구줄의 ◫ 버튼으로 **평소 작업 중에도** 도킹합니다. 우리 창이 한글을 감싸고, 창을 옮기면 한글이 따라오고, 최대화·최소화도 한 창처럼 움직입니다.

동작 규칙을 분명히 했습니다.

- **지금 열려 있는 한글을 그대로 감쌉니다.** 새 문서를 만들거나 파일을 여는 창을 띄우지 않습니다 — 도킹은 창을 감싸는 일이고, 문서를 여는 일은 한글에서 할 일입니다.
- **도킹 중에는 우리 창이 늘 한글 아래에 깔립니다.** 한글 문서가 아닌 영역을 눌러도 한글이 뒤로 넘어가지 않습니다. 단, 다른 프로그램을 쓰는 중에는 손대지 않습니다 — 그때 한글을 올리면 남의 창을 가로채는 짓이 됩니다.
- **버벅임이 없습니다.** 예전 추적은 30ms 폴링 + 완화(일부러 천천히 따라붙기)라 그 둘이 곧 버벅임이었습니다. 창이 움직이는 순간 이벤트 훅으로 깨어나 한 번에 스냅합니다 — 실측으로 끌기 중 어긋남 평균 34px → **0px**, 300px 점프 후 정착 592ms → **2.5ms**, 60fps 끌기 흉내에서 60프레임 중 59프레임이 0px 였습니다.
- **판 자리를 우리 창에서 액자처럼 오려 냅니다.** 처음에는 창 순서(z순서)로 풀려 했는데, 활성 창을 맨 위에 두려는 윈도우와 계속 다투게 되어 판이 하얗게 덮였습니다. 판 자리에는 아예 창이 없게 오려 내면 다툴 것이 없습니다 — 그림도 클릭도 구멍 아래의 한글이 받습니다.
- **한글 창을 판 안에 넣는 임베드(SetParent)는 실측 끝에 뺐습니다.** 부모 창이 죽으면 한글이 저장 프롬프트 없이 함께 죽고, 강제 종료 시에는 저장 안 된 원고를 안은 유령 프로세스가 남는 것까지 확인했습니다. 도킹은 창 둘이 끝까지 남남이라, 이 프로그램이 어떻게 죽든 한글과 문서는 무사합니다.
- **한글 제목줄은 그대로 보입니다.** 제목줄을 잘라 내는 시도를 했다가 철회했습니다 — 배율 환경에서 좌표계가 어긋나 리본(파일·편집·서식 도구줄)까지 날아가는 것을 실측으로 확인했습니다. 화면이 잘 보이고 부드럽게 따라오는 쪽이 우선입니다.
- **도킹 중 도구줄은 공통(왼쪽) / 개인(오른쪽)으로 갈립니다.** '물감 [팔레트]' 머리줄을 없애고 팔레트 고르기를 개인 구역 머리로 옮겨 한 줄을 통째로 줄였습니다. 물감 도구줄 두께는 세 줄로 고정해, 칩이 늘어도 한글이 위아래로 밀리지 않습니다.

### 문항 엑셀 — 표에 채우면 문항이 됩니다

마크다운을 치는 것 자체를 힘들어하는 분을 위한 길입니다. 엑셀 양식을 내려받아 칸을 채우고, 그 파일을 불러오면 시험 문항으로 변환됩니다. 창에는 '이 창에서 할 수 있는 것' 안내를 붙여, 처음 열어도 무엇부터 하면 되는지 보이게 했습니다.

### 도구줄이 PNG 아이콘 한 벌이 됐습니다

유니코드 기호는 글꼴이 정한 크기대로 그려집니다 — 같은 15px 로 찍어도 ⚙ 는 꽉 차고 ⌕ 는 눈에 절반이었습니다. 획 굵기를 상자 비율로 잡아 이미 구워 둔 아이콘 한 벌(assets/icons)이 있었는데 앱이 안 쓰고 있었고, 그 연결을 이었습니다.

- **포인트 컬러** — 획은 회색 그대로, 안쪽 요소 하나만 앱 강조색입니다(톱니 가운데 원, 되돌리기 화살촉, 렌즈 안쪽 등). 색 면적이 5분의 1 안쪽이라 아래 물감 블럭과 무게가 겹치지 않습니다.
- **'항상 위'는 층 세 장** — 압정은 '고정'이지 '가장 위'가 아니었습니다. 층을 셋 쌓고 맨 위 한 장만 포인트색으로 두면 '다른 것들 위에 있다'가 그림 그대로 읽힙니다.
- **도킹 아이콘 신규** — 창 안에 도구줄과 문서가 든 모습.
- **버튼 26 → 32px, 아이콘 20 → 24px.** 26px 은 접근성 최소선(24)을 2px 넘겼을 뿐이라 빠듯했습니다.
- **도움말은 맨 뒤로, 그 앞에 구분선** — 앞쪽은 자주 쓰는 것, 구분선 뒤는 드물게 쓰는 것.

## 2. 화면별 상세

### 메인 창

- 블럭이 흰 카드 + 이름 위 아이콘이 됐습니다. 아이콘 줄이 들어가면서 두 줄 이름이 잘려, 칸을 42 → 58px 로 키웠습니다.
- **블럭 이름이 자리가 남는데도 잘리던 것을 고쳤습니다.** '칸당 2자' 상수가 26px 칸 시절 값인데, 그 뒤 칸이 58px 로 커지는 동안 이 숫자만 남아 있었습니다. 이제 실제 칸 폭 ÷ 글자 폭으로 계산하고, 글자 수가 아니라 **표시 폭**으로 셉니다 — 공백·숫자는 한글의 절반이라, '마크다운 변환'(7자)과 '마크다운변환'(6자)이 같은 자리를 쓰는데 하나만 잘리던 문제도 같이 없어졌습니다.
- **사진 블럭 아이콘이 진짜 그림이 됐습니다.** 액자+산+해 벡터가 이미 그려져 있었는데 앱은 글자(▨)로 대신하고 있었습니다 — 무채색 판으로 구워 연결했습니다. 서식 조합 아이콘은 "가a"(한글+라틴 소문자)로 — 완전한 두 음절 "가나"는 다른 아이콘의 거의 두 배 면적이라 무게가 안 맞았습니다.
- **정적 메뉴 라벨에서 말줄임표를 뺐습니다.** 팔레트 내보내기/불러오기, 파일에서 직접 고르기 등. 이름이 길어 잘렸음을 표시하는 동적 말줄임표는 별개 기능이라 그대로입니다. 겸사겸사, "'팔레트 관리'에서 팔레트를 만들어보세요" 안내문이 이미 없어진 메뉴를 가리키고 있던 것을 "⚙ 설정에서 팔레트를 만들어보세요"로 바로잡았습니다.

### 팔레트 설정

- **미리보기가 메인 창과 같은 얼굴이 됐습니다.** 예전에는 자르는 기준(글자 수 vs 표시 폭)이 달라 같은 블럭이 두 화면에서 다른 물건처럼 보였고, 메인 창 글자 크기를 그대로 옮기니 작은 칸에서 아이콘이 세로를 다 차지해 이름이 짓눌렸습니다. 이제 메인 창 칸 대비 이 칸의 **비율**만큼 아이콘·글자를 줄입니다 — 절대 크기는 달라도 '아이콘 위 이름 한 줄'이라는 배치가 같은 모양입니다.
- **블럭을 고르면 물감 창고와 같은 규칙으로 파랗게 물들고 테두리가 생깁니다.** 예전에는 테두리만 굵어지고 배경은 흰색이라 고른 티가 안 났고, 라벨 위젯이 테두리 아랫변을 가려 테두리가 이상하게 보였습니다. 배경·테두리·글자색을 함께 바꾸고, 라벨을 가장자리에서 물려 테두리가 온전히 보이게 했습니다.
- **이름이 칸을 넘으면 자르는 대신 글자를 한 단계씩 줄여 맞춥니다.** 잘린 이름은 무엇인지 알 수 없지만, 한 단계 작은 이름은 그대로 읽힙니다. 최소 크기로도 안 들어가는 아주 긴 이름만 자릅니다.
- **이름을 가운데 정렬로 통일하고 줄 높이를 10px 확보했습니다.** 아이콘 없는 개인 블럭만 왼쪽 정렬로 남아 줄이 안 맞아 보였고, 글자가 카드 위쪽 테두리에 닿아 보였습니다. 칸 폭을 키우면 '창 폭 유지' 결정과 부딪히므로 세로만 늘렸고, 클릭 판정도 가로/세로 두 축으로 분리해 아래쪽 줄 클릭이 위로 밀리는 회귀를 막았습니다.
- **팔레트 관리(⋯) 메뉴가 자체 팝오버가 됐습니다.** 윈도우 기본 회색 메뉴 대신, 드롭다운을 유지한 채 그 줄 오른쪽으로 계단식으로 펼쳐집니다 — 한글의 계단식 메뉴와 같은 무늬라 손에 익은 동선 그대로입니다.
- **탭 관리 메뉴는 고르기 버튼 바로 아래에 고정해 엽니다.** 마우스 위치에 열면 목록 아래쪽에서 메뉴가 격자를 덮어, 탭 고르개가 가려 보이지 않는 것처럼 느껴졌습니다.

### 물감 창고

- **색을 맞바꿨습니다 — '고른 것'=파랑, '쓰는 중'=초록.** 앱의 강조색 파랑은 이제 '지금 내가 고른 것'을 말합니다. v0.2.0 에서 파랑을 '쓰는 중'에 줬는데, 선택 표시와 상태 표시 중 더 즉각적인 쪽이 강조색을 갖는 것이 맞았습니다.
- **범례에서 '안 씀' 칸을 뺐습니다.** 안 쓰는 물감은 원래도 흰 카드 그대로라, 색 없는 상태를 위해 색 견본을 그리는 것이 모순이었습니다.
- **격자와 창고의 선택이 동시에 남던 버그를 고쳤습니다.** 격자 타일을 고르면 창고 선택이 지워지고, 물감을 고르면 격자 선택이 지워집니다 — 한 번에 하나만 파랗습니다.
- 카드의 이름·빈칸 수 라벨을 가운데 정렬로 통일했습니다.

### 대화상자

- **도구 선택이 두 줄 목록이 됐습니다.** 콤보박스 한 줄에서는 설명이 잘렸습니다 — 이제 이름 + 설명 두 줄로 나란히 놓고 고릅니다.
- **특수기호/문구 블럭 만들기에 기호 격자가 붙었습니다.** 입력창 하나뿐이라 기호를 밖에서 복사해 와야 했는데, 내장 기호 470여 개를 검색해 바로 골라 넣을 수 있습니다.
- **양식 블럭 편집이 생겼습니다.** 등록된 양식 중에서 바꿔 답니다.
- **도구 블럭의 '편집' 오동작을 막았습니다.** 마크다운 변환 같은 도구 블럭에서 '편집'을 누르면 서식 조합 창이 열렸습니다 — 편집은 서식 조합 블럭에만 뜹니다.

- 팔레트 격자와 물감 창고의 선택이 동시에 남던 것 — 한 번에 하나만
- 블럭 이름이 칸에 자리가 남는데도 잘리던 것 — 낡은 '칸당 2자' 상수를 실제 칸 폭 ÷ 글자 폭으로, 표시 폭 기준으로
- 설정 미리보기가 메인 창과 다른 기준으로 잘리던 것 · 이름 아랫부분이 1px 모자라 점선처럼 보이던 것(칸 34 → 44px) · 아이콘이 세로를 다 차지해 이름이 짓눌리던 것
- 팔레트 설정 선택이 테두리만 굵어지고 배경은 흰색이던 것 · 라벨이 선택 테두리 아랫변을 가리던 것
- 그림 아이콘(사진)이 옆 글자 아이콘보다 커 보이던 것 — pt→px 환산이 이중으로 적용돼 배율이 붙어 있었음
- 도구 블럭의 '편집'이 서식 조합 창을 열던 것
- 문항 엑셀 창 버튼이 화면을 채울 만큼 커지던 것
- 안내문이 이미 없어진 메뉴('팔레트 관리')를 가리키던 것
- 탭 관리 메뉴가 격자를 덮어 탭 고르개가 가려 보이던 것
- 개인 블럭 글자가 카드 위쪽 테두리에 닿아 보이던 것 · 왼쪽 정렬로 줄이 안 맞아 보이던 것
- 호버 시간이 토큰(130ms)과 코드(128ms)로 갈라져 있던 것 — 코드가 토큰을 읽게 배선

도킹을 만드는 동안 생겼다 잡은 것들(문서가 두 개 열림, 한글이 클릭·타자를 못 받음, 판이 하얗게 덮임, 뗀 뒤 좌표가 밀림 등)은 1장에 함께 적었습니다 — v0.2.0 사용자가 겪던 버그는 아닙니다.

## 4. 알려진 제한

- **한글 제목줄은 도킹 중에도 그대로 보입니다.** 잘라 내면 배율 환경에서 리본까지 날아가는 것을 실측으로 확인하고 철회했습니다.
- **"팔레트 세부 설정이 디자인 언어와 다르다"는 지적은 남아 있습니다.** 구체 지점을 짚지 못해 이번에는 손대지 않았습니다 — 어디가 다른지 짚어 주시면 그 부분부터 고칩니다.
- **공통 팔레트 블럭 아이콘의 그림 자체는 추후 바꿀 예정입니다.** 크기·배치는 이번에 확정했고, 그림은 남겨 뒀습니다.
- **막바지 화면 수정 일부는 자동 검증을 생략했습니다.** 사용자가 화면으로 직접 확인하는 방식을 택한 수정들입니다 — 문제가 보이면 알려 주십시오.
- **스크립트 블럭과 제작용 MCP 는 설계 검토만 마쳤습니다** (제한 파이썬 방식으로 방향 결정, 미구현).
- **exe 는 여전히 코드 서명이 없습니다.** 백신·SmartScreen 이 경고할 수 있습니다.

## 5. 올릴 때 알아 두실 것

- **그냥 덮어쓰면 됩니다.** '내 물감' 폴더 구조, `config.json` · `library.json`, 주고받기 파일 형식(`.hwpal`)이 전부 그대로라 데이터 이관이 없습니다. 화면이 크게 바뀌었지만 저장된 것은 아무것도 바뀌지 않았습니다.
- **소스로 실행하며 문항 엑셀을 쓰려면** `openpyxl` 이 필요합니다 (exe 에는 들어 있습니다).
- 서명이 없어 윈도우·백신이 경고를 띄울 수 있습니다.

**검증** — 자동 테스트 549개 통과 · 도킹 실측(끌기 60프레임 추적 오차 · z순서 3경우 · 원복 좌표) · 막바지 화면 수정 일부는 사용자 직접 확인 방식.

한글(HWP) 수업·행정 문서를 빠르게 만드는 팔레트 도구의 세 번째 공개판입니다. **화면 전면 개편**, 메인 창이 한글을 감싸는 **도킹**, 엑셀 표로 시험 문항을 만드는 **문항 엑셀**, 그리고 눈에 안 보이는 곳의 **데이터 보호와 속도 대공사** — 넷으로 요약됩니다.

앞선 [v0.2.0](../../releases/tag/v0.2.0)은 기록용으로만 공개했으므로, **실제로 내려받아 쓰는 판으로는 v0.1.1 다음이 이 판**입니다. v0.2.0의 변경도 이 노트에 함께 정리했습니다.

## 1. 한글과 도킹 — 두 창이 한 몸이 됩니다

도구줄의 도킹 버튼을 누르면 메인 창이 **지금 열려 있는 한글**을 감쌉니다. 새 문서를 만들지 않고 창을 감싸기만 합니다 — 도킹은 창을 감싸는 일이고, 문서를 여는 일은 한글에서 할 일입니다. 창을 옮기면 한글이 따라오고, 최대화·최소화도 한 창처럼 움직입니다.

**전** — 팔레트가 문서를 가리고, 한글을 옮겨도 따라오지 않음
**후** — 팔레트가 한글을 액자처럼 감싸고 함께 움직임. 판 자리의 그림도 클릭도 아래의 한글이 받음

| 측정 항목 | 전 (폴링 30ms + 완화) | 후 (이벤트 훅 + 즉시 스냅) |
|---|---|---|
| 끌기 중 두 창의 어긋남 (평균) | 34px | **0px** (60프레임 중 59프레임 0px) |
| 300px 점프 후 제자리 정착 | 592ms | **2.5ms** |

- **판 자리를 우리 창에서 액자처럼 오려 냅니다**(SetWindowRgn). 처음에는 창 순서(z순서)로 풀려 했는데 활성 창을 맨 위에 두려는 윈도우와 계속 다투게 되어 판이 하얗게 덮였습니다. 판 자리에 아예 창이 없게 오려 내면 다툴 것이 없습니다.
- **도킹 중에는 우리 창이 늘 한글 아래.** 한글 문서가 아닌 영역을 눌러도 한글이 뒤로 넘어가지 않습니다. 다른 프로그램을 쓰는 중에는 손대지 않습니다 — 그때 한글을 올리면 남의 창을 가로채는 짓이 됩니다.
- **한글 창을 판 안에 넣는 임베드(SetParent)는 실측 끝에 뺐습니다.** 부모 창이 죽으면 한글이 저장 확인 없이 함께 죽고, 강제 종료 시 저장 안 된 원고를 안은 유령 프로세스가 남는 것까지 확인했습니다. 도킹은 창 둘이 끝까지 남남이라, 이 프로그램이 어떻게 죽든 한글과 문서는 무사합니다.
- **도킹 중 도구줄은 공통(왼쪽) / 개인(오른쪽)으로 갈립니다.** 두께는 세 줄 고정 — 칩이 늘어도 한글이 위아래로 밀리지 않습니다.
- 한글이 응답하지 않을 때 도킹 해제가 함께 멈추던 경로도 제거했습니다.

## 2. 문항 엑셀 — 표에 채우면 시험 문항이 됩니다

마크다운을 치는 것 자체가 힘든 분을 위한 새 길입니다.

```
① 엑셀 양식 내려받기 → ② 번호·유형·질문·선지를 칸에 채움 → ③ 팔레트로 불러오기 → ④ 한글 시험지 표 완성
```

- 유형별 스타일(선다형·합답형 등)을 **양식 파일이 스스로 기억합니다** — 나중에 읽어도 같은 틀로 나갑니다.
- 사진 칸은 연결된 사진 폴더의 그림 이름을 드롭다운으로 골라 넣습니다.
- 정답표 복사·마크다운 복사 버튼으로 결과를 바로 옮길 수 있습니다.
- 창에 '이 창에서 할 수 있는 것' 안내를 붙여, 처음 열어도 무엇부터 하면 되는지 보이게 했습니다.

## 3. 화면 전면 개편 — 목업으로 고르고, 고른 것만 넣었습니다

코드를 바로 고치지 않았습니다. 지금 실행 중인 창을 그대로 옮긴 목업으로 **한 번에 한 가지씩만 바꾼 시안**(메인 창 6종 · 격자 칸 3종 · 도구줄 5안)을 눈으로 비교해 확정한 뒤, 확정된 것만 구현했습니다. 글자 위계나 격자 칸 크기는 숫자만 보고 정할 수 없기 때문입니다.

| | 전 (v0.1.1) | 후 (v0.3.0) |
|---|---|---|
| 블럭 | 종류별 파스텔 배경 — 여덟 개만 돼도 이름보다 색 덩어리가 먼저 보임 | **흰 카드 + 이름 위 아이콘** — 종류는 아이콘이 말하고 색은 강조에만 |
| 글자 위계 | 5단 (가운데 세 단계가 1pt 간격 → 절반이 위계 없음) | **4단** (실제 17/15/12/10pt) |
| 도구줄 | 유니코드 기호 — 같은 15px로 찍어도 제각각 | **PNG 아이콘 한 벌**, 버튼 26 → 32px |
| 격자 칸 | 42px | 58px (설정 격자는 최소 24px, WCAG 2.5.8) |

![도구줄](https://raw.githubusercontent.com/seungyeon980808-pixel/HwpPalette/main/docs/images/02-topbar.png)

![되돌리기 활성](https://raw.githubusercontent.com/seungyeon980808-pixel/HwpPalette/main/docs/images/02b-topbar-undo-on.png)

> 되돌릴 것이 생기면 ↺ 가 진해집니다

- **공통 팔레트는 아이콘 주도, 개인 팔레트는 글자만.** 개인 블럭은 종류가 몇 가지 안 돼서, 같은 기호가 스무 칸 반복되면 뜻이 아니라 무늬가 됩니다. 공통 아이콘은 이후 25% 축소(16→12pt) — 아이콘이 이름을 누르는 느낌이었습니다.
- **아이콘에 이모지는 쓰지 않습니다** — 윈도우에서 컬러로 그려져 색을 아낀 뜻이 깨집니다.
- **도구줄 아이콘의 색은 한 점만.** 획은 회색, 안쪽 요소 하나만 강조색(면적 1/5 이내). '항상 위'는 압정 대신 층 세 장 — 압정은 '고정'이지 '가장 위'가 아닙니다.
- **사진 블럭 아이콘이 진짜 그림이 됐습니다** (액자+산+해 벡터를 무채색 판으로 구워 연결).
- **블럭 이름이 자리가 남는데도 잘리던 것** — 낡은 '칸당 2자' 상수를 실제 칸 폭 ÷ 글자 폭, 글자 수가 아니라 **표시 폭** 기준으로 바꿔 해결했습니다.
- **디자인 토큰을 실제 코드와 맞췄습니다.** 움직임 토큰(MOTION)이 정의만 되고 읽히는 곳이 0곳이던 것을 배선하고, 값은 실측치 128ms로 통일했습니다(16ms 프레임 주기의 배수여야 중간 색이 버려지지 않습니다).

## 4. 팔레트 설정 — 끌어서 만들고, 누르는 대로 따라옵니다

![팔레트 설정](https://raw.githubusercontent.com/seungyeon980808-pixel/HwpPalette/main/docs/images/03-settings.png)

> 왼쪽 배치 격자 · 가운데 물감 창고 · 오른쪽 미리보기

| | 전 | 후 |
|---|---|---|
| 칸·줄 조절 | `− 8 ＋` 버튼이 숫자 양옆에 갈라짐 | **`8 ▲▼` 위아래 스피너** 한 곳에 |
| 선택 표시 | 테두리만 굵어지고 배경은 흰색 · 라벨이 테두리를 가려 끊겨 보임 | **파란 배경 + 온전한 테두리** (창고와 같은 규칙) |
| 블럭 클릭 | 클릭마다 격자 전체 재구축 → 버벅임 | **그 칸만 갱신** |
| 블럭 드래그 | 매 칸 이동마다 위젯 250여 개 전부 다시 칠 | **지나간 칸과 새 칸만** |

- **미리보기가 메인 창과 같은 얼굴.** 자르는 기준을 통일하고, 메인 창 칸 대비 이 칸의 **비율**만큼 아이콘·글자를 줄입니다 — 절대 크기는 달라도 '아이콘 위 이름 한 줄'이라는 배치가 같은 모양입니다.
- **이름이 칸을 넘으면 자르는 대신 글자를 한 단계씩 줄입니다.** 잘린 이름은 무엇인지 알 수 없지만, 한 단계 작은 이름은 그대로 읽힙니다.
- **모서리 손잡이를 끌어 블럭 크기를 한 번에.** 우클릭 '가로 +1'을 다섯 번 누르던 일이 끌기 한 번이 됐습니다.
- **팔레트 관리(⋯)가 자체 팝오버 계단식 메뉴가 됐습니다** — 윈도우 기본 회색 메뉴 대신, 드롭다운을 유지한 채 그 줄 오른쪽으로 펼쳐집니다. 한글의 계단식 메뉴와 같은 무늬라 손에 익은 동선 그대로입니다.

## 5. 물감 창고와 미리보기 — 한 벌로 묶었습니다

창고와 미리보기는 같은 물감을 고르고 들여다보는 한 벌이라 테두리 하나로 묶고, 사이는 1px 선으로만 가릅니다. 미리보기는 늘 떠 있고 내용만 바뀌며, 그림이 커지거나 작아져도 버튼 줄은 절대 움직이지 않습니다.

![물감 창고](https://raw.githubusercontent.com/seungyeon980808-pixel/HwpPalette/main/docs/images/04-store.png)

![물감 미리보기](https://raw.githubusercontent.com/seungyeon980808-pixel/HwpPalette/main/docs/images/05-preview.png)

- **색 규칙을 맞바꿨습니다 — '고른 것'=파랑(강조색), '쓰는 중'=초록.** 선택 표시와 상태 표시 중 더 즉각적인 쪽이 강조색을 갖는 것이 맞았습니다.
- **범례에서 '안 씀' 칸 제거** — 안 쓰는 물감은 원래 흰 카드 그대로라, 색 없는 상태를 위해 색 견본을 그리는 것이 모순이었습니다.
- **격자와 창고의 선택이 동시에 남던 버그 수정** — 한 번에 하나만 파랗습니다.
- **양식·템플릿을 프로그램 안에서 고칩니다.** 미리보기에서 바로 '수정'으로 이어지고, 고치는 동안 한글 편집 창이 이 창에 도킹됩니다.

## 6. 특수기호 격자 — 470여 개를 검색해 바로 고릅니다

입력창 하나뿐이던 특수기호·문구 등록에, 내장 기호 470여 개를 묶음별로 훑거나 검색해 바로 고르는 격자가 붙었습니다. 고르면 문서에서 부르는 법(`\원1\` 같은 라벨)을 바로 알려줍니다.

도구 선택 대화상자도 콤보박스 한 줄에서 **이름 + 설명 두 줄 목록**으로 바뀌어, 무엇을 고르는지 보입니다. 콤보박스에서는 설명이 잘렸습니다.

## 7. 되돌리기와 데이터 보호 — 이번 릴리즈에서 가장 공들인 부분

v0.1.1 이후 두 차례에 걸쳐 데이터를 지키는 공사를 했습니다. 먼저 **문서 쪽**(v0.2.0분) — 빈 문서가 원본 물감을 덮어쓰던 것, 변환 실패 시 사용자 글이 사라지던 것을 막고 ↺ 되돌리기를 새로 만들었습니다. 이어서 **전면 감사** — 전체 코드를 진단해 조용히 잘못되던 위험 지점 40여 곳을 고쳤습니다.

![되돌리기](https://raw.githubusercontent.com/seungyeon980808-pixel/HwpPalette/main/docs/images/10-undo.png)

### 팔레트·물감 데이터가 사라지지 않습니다

**전** — 설정 파일 손상(백신·클라우드 동기화가 잠깐 잠근 경우 포함) → 빈 값으로 시작 → 다음 저장 → **팔레트 전체 소실**

**후** — 설정 파일 손상 → **백업(.bak1~3)에서 자동 복구** → 그대로 사용
복구까지 실패하면 → **저장 자체를 잠그고 안내** (원본은 `.damaged`로 보존)

모든 저장은 임시 파일에 쓴 뒤 통째로 바꿔 끼우는 **원자적 방식**으로 통일했습니다 — 쓰는 도중 전원이 나가도 반쪽짜리 파일이 남지 않습니다.

### 되돌리기(↺)는 정직합니다

**전** — 변환 → 사용자가 문단을 직접 씀 → ↺ → **직접 쓴 문단까지 지워질 수 있었음**

**후** — 같은 상황에서 ↺ → **멈추고 이유를 말합니다**: "변환 뒤에 직접 고친 내용이 있어 자동 되돌리기를 멈췄습니다 — 한글의 Ctrl+Z 를 써 주세요"

문서가 바뀌었거나 다른 탭이 활성화됐어도 마찬가지로 실행하지 않고 이유를 말합니다.

### 시험지가 조용히 틀리지 않습니다

| 입력한 것 | 전 — 시험지에 찍히던 것 | 후 |
|---|---|---|
| 선지 "ㄱ만 옳다" | "ㄱ" | **"ㄱ만 옳다"** |
| 보기 ㄱ·ㄴ·ㄷ 순서 | 길이순으로 재정렬 — 정답표 어긋남 | **쓴 순서 그대로** |
| 양식 빈칸 6개 | AI에 "12개"로 안내 — 답이 한 칸씩 밀림 | **정확히 6개** |
| 이름이 안 맞는 빈칸 | 전부 지우고 "완성"으로 보고 | **그대로 두고 몇 개인지 보고** |

### 그 밖의 안전 수정

- **빈 문서가 원본 물감을 덮어쓰던 것 차단** — 캡처·저장 경로 3중 가드 (v0.2.0분)
- **변환이 실패해도 사용자 글이 사라지지 않습니다** — 실패 시 지운 선택 영역을 되살리거나 클립보드로 구출합니다 (v0.2.0분)
- **편집 저장 전 활성 문서 확인** — 실패하면 문서를 건드리기 전에 중단합니다. 사용자가 보던 다른 탭의 문서가 수정되던 경로를 막았습니다
- **복사가 실제로 됐는지 확인한 뒤에만 클립보드를 믿습니다** — 예전 복사 내용이 "선택 영역"으로 둔갑해 진짜 선택을 덮어쓰던 사고 차단
- **오류가 어디에도 안 남던 것** → `내 물감/app.log` 기록 + 알림 창. 시작 실패도 안내 창이 뜹니다
- **프로그램 이중 실행 차단** (설정을 서로 덮어쓰는 사고 방지)
- 확인 창이 떠 있는 동안 단축키를 또 눌러도 변환이 겹쳐 돌지 않습니다

## 8. 자리 문법 확정과 접이식 안내

양식·템플릿의 빈칸 표기를 확정했습니다 — 짝 없는 홑 `\` 대신 **`\ \` 쌍**이 자리 하나, **`\학년\`** 처럼 이름을 심으면 표에서 이름으로 채웁니다. 서식은 쉼표로 구분합니다.

## 10. 속도와 매끄러움 — 측정하고 고쳤습니다

### 시작 4.4초 → 약 0.6초

한글 제어 라이브러리가 시작 시점에 쓰지도 않는 것(pandas 1.4초, COM 형식 정보 1.3초)까지 끌고 오던 것을, 실제로 필요한 **첫 연결 순간**으로 미뤘습니다.

```
전  ████████████████████████████████████████  4.4초
    pandas 1.4s │ COM 형식 1.3s │ 기타 1.1s │ UI 0.6s

후  █████                                     0.6초
    UI 0.6s   (한글 라이브러리 3.8초는 첫 변환 순간으로 이동)
```

### 창이 뜨는 방식

**전** — 엉뚱한 자리에 반쯤 그려진 채 등장 → 제자리로 점프
**후** — 숨긴 채 완성 → 제자리 배치 → **0.12초 페이드인** (빠르게 떠서 부드럽게 정착)

무거운 재구축은 베일(살짝 어두워졌다 밝아지는 전환)이 가려 덜컹임이 보이지 않습니다.

### 측정으로 확인한 개선

| 항목 | 전 | 후 |
|---|---|---|
| 프로그램 시작 | 약 4.4초 | **약 0.6초** |
| 가만히 있어도 앱이 얼던 것 (v0.1.1) | 2~3초 주기 상태 폴링이 한글이 바쁠 때마다 UI를 붙듦 | **폴링 제거** — 필요한 순간에만 확인 |
| 특수기호 창 열기 | 격자를 최대 3번 지은 뒤 표시 (위젯 850개) | **즉시 표시** — 여섯 줄 먼저, 나머지는 뒤에서 |
| 사진 버튼 | 한글 연결 + 폴더 전체 스캔 후 목록 표시 | **목록 즉시** — 연결은 넣는 순간, 폴더 수는 캐시 |
| 설정에서 블럭 클릭 | 클릭마다 격자 전체 재구축 | **그 칸만 갱신** |
| 물감 설정 목록 (항목 수백 개) | 다 그릴 때까지 창이 굳음 | **창 먼저, 목록은 나눠 그리기** |
| 양식 채우기 대기 | 말없이 굳어 있음 | **"한글에서 변환 중입니다…"** 표시 |
| 도킹 추적 | 어긋남 34px · 정착 592ms | **0px · 2.5ms** |

## 12. 알려진 제한

- **코드 서명이 없어** SmartScreen·백신이 경고할 수 있습니다 — [추가 정보] → [실행]으로 진행하세요.
- **도킹 중에도 한글 제목줄은 그대로 보입니다.** 잘라 내면 배율 환경에서 좌표계가 어긋나 리본(파일·편집·서식 도구줄)까지 날아가는 것을 실측으로 확인하고 철회했습니다.
- **줄바꿈·탭이 안에 섞인 양식 빈칸은 표로 채울 수 없습니다** — 대신 몇 개인지 알려주고, 표시를 지우지 않고 열어 줍니다.
- **공통 팔레트 블럭 아이콘의 그림 자체는 추후 바꿀 예정입니다** (크기·배치는 이번에 확정).
- **스크립트 블럭과 제작용 MCP는 설계 검토만 마쳤습니다** (제한 파이썬 방식으로 방향 결정, 미구현).
- 한글(HWP)이 설치된 Windows에서만 동작합니다.

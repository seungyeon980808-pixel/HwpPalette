## 1순위 — 빈 설치에서 튜토리얼이 깨지는 문제 (약 30분)

### 무엇이 문제인가

갓 설치한 사람(빈 라이브러리)으로 튜토리얼 예문을 돌려 본 결과:

```
!! [처음 시작하기] 수능 양식으로 새 문서 열기
      등록되지 않은 라벨: \수능양식\
!! [템플릿] 꺼내 쓰기 / 비울 칸과 여러 줄
      등록되지 않은 라벨: \가정통신문머리\
```

`\수능양식\` 은 **박승연 개인 library.json 에만 있다.** 새 사용자는 '처음
시작하기' 실습 2에서 실패한다. 첫인상 화면이라 아쉽고, **이미 v0.1.1 릴리즈에
실려 나갔다.**

템플릿 코스 쪽(`\가정통신문머리\`)은 그 코스 안에서 직접 만들게 되어 있어
덜 심각하지만, 이름을 다르게 지으면 역시 실패한다.

### 어떻게 고치나 (둘 중 택일 — 내일 판단)

**(가) 그 자리에서 우아하게 넘어가기 — 싸다**
- `tutorials.py:116` 의 `\수능양식\` 실습을, 라벨이 등록돼 있을 때만 보여준다.
- 방법: 단계에 `"needs_label": "수능양식"` 같은 조건을 두고, `tutorial.py`
  의 `_show` 에서 없으면 그 단계를 건너뛴다. 또는 안내문에 "이 실습은 양식을
  등록한 뒤에 할 수 있습니다" 를 띄우고 [다음] 으로 흘려보낸다.
- 장점: 30분. 단점: 새 사용자는 여전히 양식을 못 배운다.

**(나) 내장 시작 꾸러미 — 근본 해결이지만 크다**
- 괜찮은 템플릿 몇 개를 **프로그램에 동봉**해 첫 실행 때 자동 등록한다.
- 선생님이 "괜찮은 템플릿들은 내장으로 넣을 생각" 이라고 하신 그 계획.
- 조각 .hwp 를 `assets/starter/` 에 넣고 `hwp_palette.spec` 의 `datas` 에
  추가 → 첫 실행에 `library.py` 가 복사해 등록.
- **주의**: spec 의 `datas` 에 개인 데이터가 섞이면 안 된다
  (`build_exe.py` 의 `PRIVATE` 검사가 막아 주지만, 새 폴더는 검사 밖이다).
- 장점: 받자마자 쓸 게 있다. 단점: 어떤 템플릿을 넣을지 선생님이 골라야 한다.

**추천**: 내일은 (가)로 막고, (나)는 칩 작업이 끝난 뒤에 한다 — (나)는
"어떤 템플릿을 내장할지" 라는 선생님 결정이 필요해서 혼자 진행할 수 없다.

## 2순위 — 칩 2단계: ref 재연결 (칩의 핵심 조각)

### 왜 이것부터인가

팔레트를 남에게 넘기려면 이 조각이 **반드시** 있어야 한다. 지금은
`import_archive` 가 물감에 새 id 를 발급하는데(`library.py:713`), 팔레트
블럭은 옛 id 를 가리키고 있어 그대로 넘기면 참조가 전부 끊긴다.

### 데이터 구조 (다시 확인할 것 없이 여기 적어 둠)

```
config.json  "palette_tabs"
  탭   = {name, cols, blocks[]}
  블럭 = {type, row, col, span, rows, ...}

  블럭 종류별 자립도:
    char     {"type":"char","value":"√"}                 ← 내용 자체 포함, 의존 없음
    function {"type":"function","actions":[...]}          ← 내용 자체 포함, 의존 없음
    builtin  {"type":"builtin","key":"convert"}           ← 프로그램 기능, 의존 없음
    template {"type":"template","ref":<id>,"template":<이름>}  ← library 참조
    form     {"type":"form","ref":<id>,"form":<이름>}          ← library 참조

library.json  서식/문자/템플릿/양식
  항목 = {id(uuid), name, label, tags[], file, slot_count, preview}

fragments/<uuid>.hwp   템플릿·양식의 실제 내용
```

**ref 를 갖는 것은 template/form 둘뿐이다.** 나머지는 블럭만 옮기면 끝.

### 할 일

1. `library.import_archive` (`library.py:685`) 가 **old_id → new_id 대응표를
   함께 돌려주게** 한다. 지금 반환은 `{"added", "renamed", "relabeled"}` 이므로
   `"id_map"` 을 더한다.
   - 그러려면 내보낼 때 원본 id 를 알아야 한다 → `export_items`
     (`library.py:643`) 가 지금 `id` 를 일부러 뺀다(`_DROP`). **`origin_id`
     라는 별도 필드로 넣는다** — `id` 를 그대로 넣으면 안 되는 이유(같은 id 가
     두 개 생기면 참조가 엉킨다)는 그대로 유효하다.
2. 탭을 받을 때 블럭의 `ref` 를 대응표로 갈아끼우는 함수를 만든다.
   - 자리: `palette.py` (탭의 소유자) 또는 새 `chip.py`. **새 파일 `chip.py`
     를 권한다** — 칩 만들기/풀기가 library·palette·settings 를 모두 건드리므로
     어느 한쪽에 넣으면 그 파일이 남의 일까지 하게 된다.
3. 회귀 테스트: 물감 3개 + 그것을 가리키는 탭 하나를 만들어 내보내고,
   **빈 라이브러리에 풀었을 때 버튼이 여전히 그 물감을 가리키는지** 확인.

### 결정해 둔 설계 (다시 논의하지 말 것)

- 칩 = zip 하나, 확장자 **`.hwpal`**
- **형식은 하나, 입구는 둘**:
  ```
  칩(zip)
   ├ manifest.json    이름·만든이·설명·버전
   ├ tab.json         ← 있으면 팔레트 칩, 없으면 물감 꾸러미
   ├ library.json     물감 목록 (id 대신 origin_id)
   └ fragments/*.hwp
  ```
- **팔레트는 통째로** 내보낸다(고를 것 없음 — 배치가 곧 가치이고, 필요한
  물감은 블럭의 ref 를 훑어 자동으로 정해진다).
  **물감은 골라서** 내보낸다(창고는 목록이라 일부만 빼도 안 깨진다).
- **등록 입구는 하나**: `⚙ → 물감 나누기 → [꾸러미 풀기]`. 팔레트 칩인지
  물감 꾸러미인지는 프로그램이 파일을 열어 판단한다.
- 등록 전에 **미리보기 + 충돌 예고** 화면을 보여준다(지금은 넣고 나서
  사후 통보라 순서가 반대다). 1단계에서는 **버튼 이름 목록**으로 충분하고,
  팔레트 배치 그림은 나중에.
- **덮어쓰기 없음**: 이름·라벨·탭 이름이 겹치면 번호를 붙인다.
- **같은 칩 두 번 받기**: `origin_id` 가 이미 있으면 물감은 건너뛰고 탭의
  ref 는 **기존 것에 연결**한다.
- **받은 물감은 태그 없이** 들어온다(이미 구현됨). 출처는 태그가 아니라
  별도 `origin` 필드 — 사용자가 지울 수 있는 태그와 성격이 다르다.
- **원자적 저장**: ①~④를 메모리에서 다 만든 뒤 마지막에 한 번에 저장한다.
  지금 `import_archive` 는 중간에 실패하면 반쯤 들어간 상태로 끝난다.
- 사진 폴더는 로컬 경로라 못 옮긴다 → 칩에 "사진 폴더 N개가 필요합니다" 만.

검진에서 나온 것 중 **유일하게 사용자 데이터를 잃는** 항목이라 여기 남긴다.

`main.py:349` 에서 `hwp_engine.delete_selection()` 으로 선택을 지운 **뒤**

돌아오지 않는다. 읽어 둔 `selected` 를 되돌려 넣는 롤백이 필요하다.

## 참고 — 오늘 알아낸 함정 (되풀이하지 말 것)

- **Tk 클립보드 금지.** `clipboard_append` 는 '주인 등록'이라 그 뒤 같은
  프로세스의 `OpenClipboard` 가 막힌다. 담기·읽기는 `clipboard.py`(win32) 로.
- **선택 읽기**는 `GetTextFile("TEXT","saveblock")` 우선. 단 이 경로는 줄표(—)
  를 `&#8212;` 로 바꿔 주므로 `_unescape_entities` 로 복원해야 한다.
- **`SelectionMode` 를 믿지 말 것.** 0 이어도 선택 내용이 읽히는 경우가 있다.
- **창 자리는 `screens.monitor_bounds()`** 로. 이 PC 는 4K(-3840~-1646)와
  세로 주모니터(0~1080) 사이에 **아무 모니터도 없는 구간**이 있어서, 합친
  범위로 재면 허공에 창이 뜬다. `popover.py` 는 아직 합친 범위를 쓴다.
- **연습 문서 닫기**는 만들 때 잡아 둔 문서 객체의 `.Close(isDirty=False)`.
  '지금 활성 문서' 를 닫으면 사용자가 옮겨 간 문서를 닫을 수 있다.

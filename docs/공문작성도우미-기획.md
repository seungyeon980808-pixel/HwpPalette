# 공문(에듀파인 기안문) 작성 도우미 — 기획

> 상태: **보류 (킵)**. 2026-07-25 기획만 정리. 구현 시작 전 아래 '먼저 정할 것' 두
> 가지를 결정해야 한다.

---

## 왜 만드나

기안문을 쓸 때 실제로 하는 일은 이렇다:

```
작년(또는 비슷한) 기안문을 찾는다  →  열어서 읽어 본다  →  베껴 쓰고 값만 고친다
```

시간을 먹는 건 **글쓰기가 아니라 '찾아서 열어보고 베끼기'** 다. 이 도구는 그
부분을 없앤다 — **고르면 바로 채워지는 것**으로 바꾼다.

---

## 쓰는 흐름 (사용자 구상)

1. 버튼을 누르면 **대략적인 틀**이 나온다 (계획 · 품의 · 보고 등 공문 종류)
2. **미리 저장해 둔 기안문 목록**에서 관련된 것을 고른다
   (드롭다운으로 고르고, 저장해 둔 PDF 로 내용을 바로 확인)
3. 그 값들이 새 문서에 **미리 채워져** 나온다 — 바꿀 것만 고치면 끝

---

## 지금 부품으로 거의 된다

| 단계 | 필요한 것 | 이 프로그램에 있는 것 |
| --- | --- | --- |
| 1. 틀 꺼내기 | 공문 종류별 골격 | **양식/템플릿 그대로** (계획·품의별로 등록) |
| 2. 지난 기안문 고르기 | 목록 + PDF 확인 | **새로 필요** ← 이것만 만들면 된다 |
| 3. 값 채우기 | 빈칸에 값 넣기 | **양식 채우기(form_fill.py) 그대로** |

즉 **새로 만들 것은 2번 하나**, "지난 기안문 서랍"이다.

---

## 2번 설계 초안

### 저장할 것 (기안문 하나당)

| 항목 | 예 |
| --- | --- |
| 제목 | 2026학년도 과학실 기자재 구입 |
| 종류 | 계획 / 품의 / 보고 |
| 날짜 | 2026-03-14 |
| PDF 경로 | 원본 공문 PDF (확인용) |
| 값들 | 사업명 · 금액 · 근거 · 예산과목 … (양식 빈칸에 넣을 것) |

### 동작

```
[공문 도우미] 누름
   → 종류 고르기 (계획/품의/보고)
   → 그 종류의 지난 기안문 목록 (드롭다운, 최근순)
   → 고르면 PDF 를 열어 내용 확인 가능
   → [이걸로 시작] → 양식을 열고 그 값들을 빈칸에 미리 채움
   → 바꿀 것만 수정
```

### 기존 구조와 잇는 법

- 저장은 `library.json` 과 같은 방식(JSON) — `공문.json` 을 따로 두는 편이
  라이브러리와 섞이지 않아 깔끔하다.
- 채우기는 `form_fill.fill()` 을 그대로 쓴다 (HWPX 의 `<hp:t>` 만 갈아끼우므로
  표·서식이 안 깨진다).
- 창은 `form_fill_ui.py` 를 본떠 만들면 된다.

## 먼저 정할 것 (구현 전)

### ① PDF 를 어디에 두나

- **(권장) 원본 위치를 가리키기만** — 학교업무 폴더의 파일 경로만 저장.
  파일이 두 벌 생기지 않고, 원본을 고치면 그대로 반영된다.
  대신 폴더를 옮기면 연결이 끊긴다(라이브러리의 '사진 폴더'와 같은 성질).
- (대안) 프로그램 폴더로 복사 — 원본을 지워도 남지만 용량이 두 배가 되고,
  기안문은 개수가 계속 늘어난다.

### ② 어디까지 자동인가

- **(권장) 지난 값을 그대로 복사** — 간단하고 결과가 예측된다. 오프라인 유지.
- (대안) 문장까지 다듬어 생성 — LLM 이 필요하다. **이 프로그램의 오프라인·
  결정론 원칙과 충돌**하므로, 하더라도 앱 밖(작성 보조)에 두는 편이 맞다.
  (같은 이유로 PDF→마크다운 변환도 앱 밖에 두기로 했다 — `docs/문법.md` 참고)

## 주의

- 공문에는 **개인정보·예산 정보**가 들어간다. 저장 위치가 프로그램 폴더면
  내보내기(zip)에 딸려 나가지 않게 분리해야 한다.
- 학교마다 양식이 다르므로 **양식은 사용자가 등록**하는 지금 방식을 유지한다
  (기능을 고정하지 않는다는 이 프로그램의 원칙 그대로).

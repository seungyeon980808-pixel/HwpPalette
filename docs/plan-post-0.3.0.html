2-2. 창고 개편 피드백 007~010 · 시안 B

  • 해시태그 폐지. 창고의 분류가 진짜 분류, 팔레트는 배치일 뿐.
  • 창고 구조(위에서부터): 제목 + 상태 필터(쓰는 중·이 팔레트·고른 것) → 분류 다섯 탭(특수기호·템플릿·서식·양식·도구, 개수 표시) → ＋ 고정 줄 → 목록.
  • ‘전체’ 분류 없음. ‘서식 조합’ → ‘서식’ 개명(탭 줄바꿈 제거). ‘도구’는 읽기 전용 분류로 정식 편입.
  • ＋ 줄은 켜 놓은 분류를 따라 글씨가 바뀜(“＋ 새 서식 만들기”). 팔레트 빈칸에서 만드는 기존 길은 그대로 유지.
  • 세 판(팔레트 설정·창고·미리보기) 폭 고정 — 가득 찬 상태 기준, 스크롤바 자리 상시 확보.
  • 창고 ↔ 미리보기 사이 간격+세로선으로 위계 분리. 미리보기는 좁게, 펼치기/접기 없음.
  • 팔레트에 못 놓는 물감은 분류가 아니라 물감 단위 표시로.

2-3. 만들기 창 피드백 012·013 · 시안 D

  • 서식 만들기 창의 수치 칸에 기본값을 미리 채움(체크는 꺼진 채) — 빈칸을 없앤다.
  • [한글에서 가져오기] 단추 — 커서 자리의 글꼴·크기·자간·줄간격·여백을 읽어 칸을 채우고 체크까지 켬. 한글의 ‘모양 복사(Alt+C)’와 같은 갈래(글자만/문단만/둘 다).
  • 이름과 마크다운 명령(라벨)도 이 창에서 함께 지정.
  • 빈칸 이름표 — 빈칸에 이름(번호·발문·보기1·선1…)을 달 수 있게 한다. 섞기·해체·문항 엑셀 전부의 바닥이 되는 결정.

2-4. 문서 해체 피드백 015 · 시안 F

완성된 시험지(hwp)를 부품으로 분해해 물감으로 등록 — 다음부터는 조립만.

  • 입구: 창고 ‘양식’에서 파일이 선택된 상태에서 [문서 해체] — 즉시 시작.
  • 항상 복사본을 열어 도킹. 원본은 손대지 않는다.
  • 도킹된 채 조작: 오른쪽에 ‘골라 담기’ 판이 임시로 나타남. 표 하나 = 조각 하나 · 문단 하나 = 조각 하나로 자동 나열(빈 문단 제외 · 표 안 문단은 표에 포함).
  • 행 클릭 → 한글에서 실물 하이라이트. 한글에서 자유 편집(지우기 · [빈칸 넣기]).
  • 필요한 행만 체크 → 잇닿은 행은 [묶어 담기] — “낱개+꾸러미로(권장) / 한 덩어리로” 선택.
  • [고른 N개 담기] — 담기 직전 재탐색으로 편집으로 밀린 위치 보정.
  • 끝나면 “담은 N개로 새 팔레트 탭을 만들까요?” — 시험지 전용 팔레트 완성.

2-5. 물감 섞기 피드백 017 · 시안 H

여러 물감을 섞어 하나의 물감으로. 요소와 조합을 분리해 “조합마다 조각 하나” 폭발을 없앤다.

  • 입구 둘: 창고 다중 선택 → [섞기] / [섞기]부터 눌러 [＋ 물감 추가]로 배열. 창 안에서 순서 끌기 + 이름.
  • 참조 방식 — 꾸러미는 요소를 가리키기만. 요소를 고치면 모든 꾸러미 반영, 요소 삭제는 경고로 막음.
  • 1차는 템플릿끼리만 섞는다.
  • 카드 표시: 칸 오른쪽 세로 MIX 리본 — 칸 높이 불변. 새 분류 없이 템플릿 분류 안에.
  • 출력: 왼쪽 클릭 = 빈칸으로 꽂기. 마크다운은 기존 문법 그대로 — \이름\ 단독 줄 + 아래 채울 줄, 값은 앞에서부터 순서대로(물감 1·2·3 빈칸 2개씩 + 여섯 줄 → 1↦①②, 2↦③④, 3↦⑤⑥). 이름표 빈칸은 이름={값}으로 자리지정 가능.
  • 빈칸 채우기 창은 기존 ‘양식 채우기’ 재사용.

2-6. 물감 겹치기 피드백 018 · 시안 G

팔레트 한 칸에 여러 물감(애플 폴더식) — 섞기와는 완전히 다른 개념: 겹치기 = 택일, 섞기 = 합체.

  • 환경설정에서 블럭을 블럭 위로 끌면 “물감을 겹치겠습니까?” → 겹친 이름 지정.
  • 겹친 칸은 겹친 종이 모양 + 개수 배지. 누르면 팝오버에서 골라 실행(특수기호 팝오버 재사용).
  • 이미 겹친 칸에 또 끌면 확인 없이 추가, 밖으로 끌면 낱개 복귀. 겹침은 배치 — 창고에는 낱개 그대로.

2-7. 문항 엑셀 피드백 014·017

  • 단계 화면(마법사)으로 재구성 — 창 밖 단계(엑셀에서 채우기)도 정식 단계로 안내.
  • 하드코딩된 유형 지도(excel_form.py:38)를 빈칸 이름표 데이터로 대체 — 사용자가 만든 템플릿·꾸러미도 엑셀에 참여.
  • 지향(상세는 섞기 구현 뒤 재설계): 행마다 꾸러미 드롭다운 + 내용 칸 + 옆 셀에 마크다운 자동 조립(수식 내장). ‘한글에 바로 넣기’ 등 자동화 폭은 그때 확정.

2-8. 자간 자동 보정 피드백 016

  • 목적: 단어가 줄 끝에서 잘리지 않으면서 줄도 헐렁하지 않게 — 줄 단위 자간 미세 조정.
  • 방식 A 확정: 어절 단위 켜고, 헐렁한 줄만 자간을 좁혀 당김. 위에서 아래로 한 줄씩(재흐름 파급 회피 — 사용자 제시 순서). 스파이크에서 줄 폭 측정이 잘 되면 양방향(방식 B)으로 상향.
  • 자간 한도(−8%~+4% 제안) · 한도 내 불가 줄은 그냥 둠 · 되돌리기(↺) 묶음에 편입.

6. 다음 라운드 버그 묶음 (031~036) — 한 라운드로 묶는다

작업 지시 사용자, 2026-08-01

docs/FEEDBACK_post_0.3.0.md 의 031·032·033·034 를 읽고, 네 건을 한 라운드로 고쳐라. 각 항목에 원인 분석과 수정 계획이 이미 적혀 있다 — 그 계획을 따르되, 계획에 적힌 실측(스파이크)을 구현 전에 먼저 하라. 032 는 “양식 수정 > 메인 도킹” 위계가 핵심이고, 034 는 여러 셀에 걸친 선택은 1차 제외다. 끝나면 테스트 전체 실행과 실기 검증 (도킹 → 양식 수정 → 저장 → 복귀, 표 안 자간 맞춤)까지 하고 main 에 병합·푸시하라. 버전은 올리지 마라.

네 건을 한 라운드로 묶는 이유: 같은 파일을 만진다. 031 과 032 는 hwp_dock.py · palette_ui.py · app.py 를 함께 건드리고, 033 과 034 는 각각 form_fill · engine_library 를 건드리되 실기 검증 경로(한글을 띄워 도킹·편집)가 겹친다. 따로 하면 같은 자리를 두 번 만지고 검증도 두 번 한다.

1

031 — 양식 수정의 세 증상

a. 창이 커짐 (원인 확정) — _exit_dock_layout() 이 접었던 판을 다시 편 직후 동기로 _fit_window() 를 부른다. 그런데 _fit_window 는 “호출부가 전부 after_idle 로 미룬다”를 전제로 스스로 update_idletasks() 를 하지 않는다 — 그 전제가 이 한 곳에서만 깨져 있다. 편집 때의 큰 값이 minsize 에 박혀 이후 줄일 수도 없다.

b. 빈 문서 남음 — hide_window_if_ours 는 “고치기 전에 없던 창일 때만” 숨긴다. 그 빈 문서 1 이 사용자 것인지 우리가 켜며 딸려온 바탕 문서인지부터 가른다. 032 를 고치면 상당 부분 함께 풀릴 가능성이 높다 (메인 도킹이 제자리로 복귀하면 그 문서는 ‘주인 있는 문서’가 된다).

c. 버벅임 — 유력 원인이 032 다. 도킹 없이도 버벅이면 hwp_dock._follow_loop 의 훅/폴링(훅 실패 시 8ms) 쪽에 원인이 따로 남는다.

031-a 는 바로 고칠 수 있다. 031-b·c 는 032 를 먼저 넣고 다시 본다.

2

032 — 도킹 소유권 위계 (이 라운드의 핵심)

한글 창의 도킹 주인은 한 번에 하나. 겹치면 더 구체적인 작업이 이긴다 — 양식 수정(편집 세션) > 메인 도킹.

hwp_dock 에 소유권 대장(claim/release, LIFO 스택)을 두고, 우선순위는 편집 세션 100 · 메인 도킹 10. pause 는 stop_follow() 만 — 창 복원은 하지 않는다(제자리로 튕겼다 다시 붙는 깜빡임 방지). resume 은 hwnd 유효성 확인 → ensure_visible() → start().

반대 방향(편집 중 메인 ◫)은 뺏지 않고 안내한다.

지금은 Dock 인스턴스 둘이 같은 hwnd 를 서로 제 판으로 끌어 SetWindowPos 를 왕복시킨다 — 사용자가 말한 버벅임의 정체.

3

033 — 빈칸 판독기 불일치 · 채워서 꽂기

a. 등록은 GetTextFile(빈칸 2), 채우기 창은 HWPX run 스캔(빈칸 1). 둘째 \ 가 글상자/그리기 개체 안이라 RUN_RE 가 못 연다. \본문\ 충돌이 아니다(실측 확정).

실측 먼저: 그 \ 가 HWPX 의 어떤 요소 안인지 부모 태그를 추적하고, 읽기를 넓혔을 때 재주입(되쓰기)도 같은 경로로 안전한지 함께 잰다 — 읽기만 넓히고 쓰기가 못 따라가면 반쪽이다.

안전망(실측이 부정적이면 이것만이라도): 채우기 창 머리에 불일치를 그대로 말한다 — “등록된 빈칸 2개 중 1개는 글상자 안에 있어 여기서 못 채웁니다” (_hidden_token_count 활용).

b. 우클릭 ‘채워서 꽂기’ 가 아직 없다 — 잔결정 목록에만 있고 미구현. “눌러도 반응이 없다”의 정체. 왼쪽 클릭 = 빈칸인 채로 실행이라는 규칙은 그대로 둔다.

4

034 — 자간 맞춤을 표 안에서도

_selected_para_range() 가 본문(list 0) 일 때만 범위를 준다. 그 아래 배관도 SetPos(0, …) 로 list 0 을 박아 쓴다. 좌표 배관 문제일 뿐이다 — 실제 구현은 폭을 재지 않고 ‘해 보고 확인’ 방식이라 셀 폭 우려는 해당하지 않는다.

범위를 (list_id, first, last) 로 넓히고 배관 전체에 list_id 를 꿴다. 줄 끝에서 다음 셀로 튀는 것을 막는 경계 방어를 더한다 (nxt[0] != list_id).

여러 셀에 걸친 선택은 1차 제외 — “셀 하나씩 선택해 주세요” 안내로 막고 셀 순회는 후속으로 남긴다.

실측 먼저(3건): ① 셀 안에서 MoveLineBegin/MoveSelLineEnd/ MoveRight 가 본문과 같게 노는가 ② SelectText 가 셀 좌표에서 동작하는가 ③ 어절 단위(ParagraphShape) 적용이 셀 문단에도 먹는가.

5

035·036 — 도킹의 z 순서 주인이 둘이다 2026-08-01 추가

035 도킹 중 팔레트 드롭다운을 열면 도킹 화면이 안 보인다. keep_order 가 fg 를 한글·우리 창 두 핸들과만 비교해서, 자체 hwnd 를 갖는 팝오버를 남의 창으로 판정하고 그냥 돌아간다 → 순서를 다시 잡아 줄 사람이 없다.

036 한글을 클릭하지 않은 채 키를 누르면 도킹 화면이 사라진다. PageUp 이 단독키로 ‘항상 위’ 토글인데(입력칸만 예외), 우리 창이 -topmost 가 되면 최상위 띠로 올라가 “한글이 맨 위 · 우리 창은 그 바로 아래”라는 도킹 계약을 매 틱 뒤집는다. 사용자는 눈앞의 한글을 스크롤하려고 누른 것인데 창 순서가 뒤집힌다.

고칠 방향(셋을 함께) — ① 도킹에 들어갈 때 -topmost 를 끄고 기억했다가 뗄 때 되돌린다(도킹 중 순서의 주인은 keep_order 하나). ② 도킹 중 PageUp·⇧ 버튼은 비켜 주고 안내 한 줄. ③ keep_order 의 ‘우리 편’ 판정을 GetAncestor(fg, GA_ROOTOWNER) 로 넓혀 팝오버·대화상자를 포함한다.

032 와 같은 파일·같은 개념이다 — 따로 하면 keep_order 를 두 번 고친다. 035 는 원인 후보가 둘이라 가르는 실측 1건(팝오버 열 때 fg·소유사슬·z순서·구멍 상태 로그)이 먼저다.

이 라운드의 검증 규약

  • 스파이크가 구현보다 먼저다 — 033·034 의 실측을 끝내고 결과를 문서에 남긴 뒤 코드를 짠다.
  • 테스트 전체 실행 (현재 728개 기준, 새 규칙은 테스트로 못박는다).
  • 실기 검증 4종 — ① 도킹 → 양식 수정 → 저장 → 메인 자동 복귀 (취소 경로도) ② 표 안(보기 박스) 문단에 자간 맞춤 → 잘림 해소 · ↺ 한 번에 원복 ③ 도킹 중 팔레트 드롭다운을 열었다 닫아도 도킹이 그대로 ④ 도킹 중 한글 미클릭 상태에서 PageUp → 도킹 유지 + 안내 (도킹을 떼면 PageUp 이 다시 ‘항상 위’로 동작).
  • 끝나면 main 에 병합·푸시.
  • 버전은 올리지 않는다 (기존 규약과 동일 — 사용자가 정한다).

7. 뒤로 미룬 것 027~030 — 이번 라운드에 넣지 않는다

왜 미루나 — 사용자 지시가 “기능 수정은 그만하고 버그를 잡자”이기 때문이다. 027(사용법)·029(사진 폴더)·030(디자인)은 기능·디자인 작업이고, 028(특수기호 분류 복원)은 회귀라 급하지만 030 과 같은 창을 만진다 — 디자인 방향을 정하기 전에 손대면 두 번 만지게 된다.

착수 순서 권함: 031~034(버그) → 028(회귀 복원) → 029(사진 폴더) → 030(디자인 통일) → 027(사용법). 028·029·027 은 모두 같은 판·같은 창을 건드리므로 디자인(030)을 마지막에 두면 재작업이 준다.

030 은 범위 결정이 먼저다 — ① 서식 창만 ② 서식 창 + 자체 부품(체크·수치칸)을 design/ 에 ③ ② + 프로그램 전체 훑기. Claude 권함은 ②.

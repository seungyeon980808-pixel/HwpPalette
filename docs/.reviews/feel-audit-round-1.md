## 요약

**feel-score 5/12 SPEC in-band** · BLOCK 4 · WARN 4 · FYI 3

토큰 **값**은 대체로 건강하다. 문제는 값이 아니라 **적용**이다.
`SP`·`RADIUS`·`FS`는 이미 쓰이고 있으나(57·34·138회) 하드코딩이 그만큼 남아 있고,
`MOTION`은 정의만 되고 **한 번도 읽히지 않는다**.

## [BLOCK] 1. MOTION 토큰이 죽어 있다

- **위치:** `hwp_palette/design/theme.py:129`
- **규칙:** §DS — 커밋된 디자인시스템 토큰은 단일 출처여야 한다 (🟢 DS)
- **증거:** `MOTION = {"hover_ms": 130, "press_ms": 0, "enter_ms": 0}` 를
  참조하는 코드가 프로젝트 전체에 **0곳**. 실제 값은 `ui_fx.py:21-22` 에
  `STEPS = 8` · `INTERVAL_MS = 16` 으로 따로 하드코딩돼 있다.
- **부수 문제:** 8 × 16 = **128ms** 인데 토큰은 **130ms** 라고 말한다.
  두 숫자가 이미 갈라졌다 — 토큰의 존재 이유가 사라진 상태.
- **수정:** `ui_fx` 가 `theme.MOTION` 을 읽게 하거나, `MOTION` 을 지운다.
  둘 중 하나여야 한다. 토큰이 거짓말을 하는 것이 없는 것보다 나쁘다.
  - 권장: `MOTION["hover_ms"] = 128` 로 정정하고 `ui_fx` 가 여기서
    `STEPS`·`INTERVAL_MS` 를 역산. 128은 16ms(60fps) 프레임 정렬값이라
    50ms 그리드 규칙(🟢)보다 이쪽 근거가 우선한다.

## [BLOCK] 2. 동심원 반경 규칙 위반 — pane

- **위치:** `hwp_palette/design/theme.py:113`
- **규칙:** §Spacing — 동심원 radius는 `outer = inner + padding` (🟢 SPEC)
- **증거:** `RADIUS = {"ctl": 6, "card": 10, "pane": 12}`
  - card(10) 안에 ctl(6) → 여백 **4** = `SP["xs"]` ✅ 맞다
  - pane(12) 안에 card(10) → 여백 **2** = SP에 없는 숫자 ❌
- **왜 문제인가:** 여백 2로 두면 SP 체계 밖 숫자를 쓰게 되고, SP를 지키려고
  여백 4를 주면 안쪽 카드 모서리가 바깥 판보다 **덜 둥글어 보인다**(눈에
  띄는 어긋남).
- **수정:** `"pane": 12 → 14`
  체인이 `6 →(+4)→ 10 →(+4)→ 14` 로 맞아떨어진다. 세 단계 모두 여백 `SP["xs"]`.

## [BLOCK] 3. 최소 히트 타깃 미달 — 격자 셀

- **위치:** `hwp_palette/ui/palette_ui.py:65`
- **규칙:** §Targets — 최소 24px (🟢 SPEC, WCAG 2.5.8) / 권장 44pt
- **증거:** `CELL_MIN_PX = 16` — 격자를 촘촘히 잡으면 클릭 대상이 16px.
  24px 하한을 8px 밑돈다. (`CELL_MAX_PX = 34` 는 통과)
- **수정:** `CELL_MIN_PX = 16 → 24`.
  격자가 넓어지면 `GRID_WIDTH_PX = 420` 안에 들어가는 열 수가 줄어든다 —
  **이건 값 하나로 못 끝내는 결정**이므로 실제 화면에서 확인 후 판단할 것.

## [WARN] 5. 간격 토큰 적용률 55%

- **규칙:** §Spacing — 8px base + 4px half-step (🟢 SPEC)
- **증거:** 하드코딩된 `padx`/`pady` 실측

  | | 그리드 위 (4·8·12·16·24) | 그리드 밖 |
  |---|---|---|
  | `padx` | 92곳 | **36곳** (10×10, 6×8, 14×7, 2×5, 3×2, 7·5·18·1 각 1) |
  | `pady` | 22곳 | **59곳** (2×18, 3×13, 1×9, 6×7, 10×4, 5·14×3, 7×2) |

- **단서:** `pady=1/2/3` 중 상당수는 **구분선(hairline)** 일 것이다 —
  그건 간격이 아니라 선 두께라 그리드 대상이 아니다. 기계적으로 다 바꾸면
  안 되고, 95곳을 한 번 훑어 "간격인가 선인가"를 갈라야 한다.
- **수정:** 진짜 간격만 `SP[...]` 로 치환. `padx=10 → SP["s"]`(8) 또는
  `SP["m"]`(12), `padx=14 → SP["l"]`(16), `padx=6 → SP["xs"]`(4).

## [WARN] 6. 글자 위계가 안 선다 — 중간 3단이 1pt 간격

- **위치:** `hwp_palette/design/theme.py:124`
- **규칙:** §Typography — UI 타입 스케일 ~1.25 (major third) (🟡 CONV)
- **증거:** `FS = {"title":12, "head":10, "body":9, "sub":8, "caption":7}` 를
  `fs()` 에 통과시킨 **실제 pt**:

  | 역할 | 논리값 | 실제 pt | 앞 단계와의 차 |
  |---|---|---|---|
  | title | 12 | 16 | — |
  | head | 10 | 13 | 3pt |
  | body | 9 | **12** | **1pt** |
  | sub | 8 | **11** | **1pt** |
  | caption | 7 | 10 | 1pt |

  비율은 1.20 / 1.11 / 1.125 / 1.14 — 전부 1.25 미달, 중간이 특히 촘촘하다.
- **왜 중요한가:** `fs(9)` 22회 · `fs(8)` 22회로 **가장 많이 쓰이는 두 크기가
  1pt 차이**다. 화면 글자의 절반이 사실상 같은 크기라 위계가 전달되지 않는다.
- **수정:** 5단 → **4단**, 논리값 간격을 2 이상으로.
  `{"title":13, "head":11, "body":9, "caption":7}` → 실제 17/15/12/10.
  `sub` 를 쓰던 22곳은 `body` 또는 `caption` 으로 흡수.

## [WARN] 7. 인접 타깃 간격 미달

- **위치:** `hwp_palette/ui/palette_ui.py:66`
- **규칙:** §Targets — 인접 타깃 간 ≥8pt (🟢 SPEC)

## [WARN] 8. 상태 레이어 농도가 밴드 밖

- **위치:** `hwp_palette/design/ui_fx.py:66-67`
- **규칙:** §Color — M3 state layer: hover 8% · pressed 10% (🟢 SPEC)
- **증거:** `HOVER_FACTOR = 0.94` (6% 어둡게) · `PRESS_FACTOR = 0.86` (14%)
  - hover 6% → 기준보다 **약함** (변화가 덜 보인다)
  - press 14% → 기준보다 **셈**
- **판단:** 방향은 맞다(누름 > 호버). 다만 간격이 필요 이상으로 벌어져 있다.
- **수정(제안):** `0.94 → 0.92` · `0.86 → 0.89`. **다만 이건 눈으로 봐야 한다** —
  숫자만 보고 바꾸지 말고 실제 화면에서 비교할 것.

## [FYI] 9. `fs()` 의 반올림이 은근히 어긋난다

- **위치:** `hwp_palette/design/theme.py:100`
- **증거:** Python `round()` 는 은행가 반올림이라 `round(12.5) = 12` (13 아님).
  `fs(10)` 이 14가 아니라 **13** 이 된다. 의도한 값인지 확인 필요.
- **수정:** 의도가 아니면 `int(size * FONT_SCALE + 0.5)`.

## [FYI] 10. veil 복귀가 이탈보다 느리다

- **위치:** `hwp_palette/design/ui_fx.py:146`
- **규칙:** §Motion — exit ≈ 0.8 × enter (🟢)
- **증거:** `veil(out_ms=110, in_ms=160)` → 비율 0.69. 기준대로면 out은 128.
- **판단:** 판을 접었다 펴는 자리라 **일부러 천천히 돌아오게** 한 것으로 보인다.
  근거가 있으면 그대로 두고, 없으면 110 → 128.

## [FYI] 11. `messagebox` 95곳

- **규칙:** §States — 컴포넌트 얼굴 통일 (🟡)
- **증거:** 기획서는 "~70곳"으로 추정했으나 실측 **95곳**. 3단계 작업량이
  기획서 추정보다 35% 크다.
